### V0 受け付け

**目的**: 自分宛ての変更を取りこぼさずに拾い、自分の決定権の中か・どのレーンか・どの深さで見るかを決め、1 回に 1 つだけ扱う。

| 段 | # | 手順 | 要点 | 出典 |
|---|---|---|---|---|
| **A1 拾う** | 1 | 受信箱を見る | レビュー待ち・問い合わせ・自分が止めたもの（HEAD が動いた）の 3 つを見る。空なら「空」と 1 行。PR を伴わない問い合わせは VQ へ | 〔GQ〕qm-session §セッション起動時〔事故〕I-20 |
| **A2 自分の仕事か** | 2 | 宛先の表を当てる | 付表 3a。R5 なら自分。R0〜R3・R7 なら**材料をそろえて渡すところまで**（Y3） | 〔GQ〕憲章 §4〔作法〕カタログ §3.2 R7（compass roles-responsibilities L756） |
| | 3 | レーンを判別する | base で判別し、レーンごとの必須の検査（アダプタ）を読む | 〔GQ〕qm-session §レビュー対象レーン |
| **A3 深さ** | 4 | 段を決める | R1〜R4 を §2b で決め、理由を 1 行（B-19）。いちばん重い軸に合わせる | 〔推論〕 |
| | 5 | 1 つずつ | 1 回に 1 つの変更。複数を一括で処理しない | 〔事故〕I-04〔GQ〕qm-session（1 Agent = 1 PR） |

- **考え方**: 受信箱が空なのは経路が壊れている兆候であることが多い〔GQ〕label-mailbox §5。自分の決定権の外の依頼は、進めるのではなく材料をそろえて渡す（Y3）
- **調査の範囲と深さ**: ここでは差分を読まない。宛先・レーン・段を決めるのに要るもの（チケットの種類・base・変更パスの一覧・触れる領域）だけ
- **背景・目的が不明なとき**: チケットが無い・受入基準が無い PR は、V2 で「受入基準が曖昧」を所見にする前提で受ける（付表 3a R2）。レーンが判別できなければアダプタの既定（いちばん重い出荷レーン）で見て、そう書く〔推論〕
- **矛盾するとき**: 依頼の label と PR の内容が食い違う（レビュー依頼に見えて実は問い合わせ）→ 内容で判定し、label を正す〔GQ〕label-mailbox §3.1.1
- **成果物と受け渡し**: 判定記録の冒頭メタ（宛先・レーン・段・理由）。次の工程は自分
- **典型的な失敗**: 複数 PR の一括処理（I-04）/ 自分の決定権の外の依頼を進める（I-24。I-26 からは QM の宛先規則が生まれた）
