### V4 検証の証拠を読む

**目的**: 「通った」を主張でなく実測で確かめる（Y5）。手順 1〜5 が段階。

| # | 手順 | 要点 | 出典 |
|---|---|---|---|
| 1 | 検査を context 単位で数える | required の一覧（アダプタ）に対し、走ったか・通ったか・skip か・未起動かを 1 つずつ。まとめの検査が緑でも根拠にしない。再トリガ後の古い世代を今の結果と読まない | 〔事故〕I-22〔GQ〕qm-session §非 pass 行 0 は緑の証明にならない |
| 2 | 作者の検証記録を読む | 実行した手順・観測した結果・受入基準を満たすと考えた理由、の 3 要素があるか。無い変更は差し戻す。PR 本文の主張を証拠として読まない（Y2） | 〔作法〕compass G-6 基準 6、Claude Code best practices〔実証〕Mitropoulos ら 2026 |
| 3 | 証跡を開く | 画像・DOM・ログ・出力の記録を実際に開き、1 件ごとに具体の所見。**差分の前後で同一の証跡は偽装を疑う**（種類ごとの判定はアダプタ。GQ は画面の記録の blob SHA） | 〔GQ〕qm-session 手順 2・3〔事故〕I-01・I-11 |
| 4 | 自分で確かめる（要るとき） | 「全件」主張は同じ grep を独立に再実行して件数を突き合わせる。手元と CI が割れたら環境差を切り分け、切り分けられなければ未確認にする。再実行で緑になったことを修正の証拠にしない（失敗条件を再現した状態の緑だけ） | 〔GQ〕qm-session §Re-Review 4、§並行セッション前提、audit-team §3.8.1 禁則 1 |
| 5 | gate を直す変更は、その gate を通す | 検査を直す PR が、直した検査に検査されないまま入らない | 〔GQ〕audit-team §3.8.1 禁則 2 |

- **考え方**: Y5。緑は証拠であって判定ではない
- **調査の範囲と深さ**: required の一覧 + 作者の記録 + 証跡。自分で再実行するのは R3 以上か、主張が「全件」「N 件」の形のとき〔推論〕
- **背景・目的が不明なとき**: required の一覧が案件に無い → context 全部を required と読み、そう書く（§6 既定）
- **矛盾するとき**: 手順 4
- **成果物**: 「走らせたもの」の欄（context 表・再実行の命令と出力）
- **典型的な失敗**: skip を緑と読む（I-22）/ 証跡を開かずに所見（I-01）
