「裏付けよ」と探すのではなく事実を並べて評価する。結論を覆しうる観測を 1 つ挙げ、それを取りに行く。他社の事例は補強であって決定の根拠ではない〔GQ〕dev-process/research-discipline §2（同節の「反証 3 件」の数字には根拠が無いので、数に依存しない形にした〔推論〕）〔作法〕Heuer の診断性\n- **調査は手段。** テストをすり抜けた不具合は、見落としていた視点を示している。同じ種類の誤りが他にないかを確かめ、検索した結果（件数と場所）を残す〔両氏〕同上（要旨）〔GQ〕dev-process/feature-change-lateral-spread\n- **理解は外注できない。** サブエージェントやツールに調べさせても、結論を自分が説明できるところまで読む。確かめたこと・推測したこと・確かめていないことを分けて書く〔両氏〕t-wada「思考は外注できるが、理解は外注できない」（Agentic Software Engineering 2026-07、[二次]: スライドの取得ツール要約）、cognitive surrender の紹介（負債のメタファー 2026-09、[一次]）\n- **頑張りではなく仕組みで気づく。** 調査で見つけた「人が気をつければ防げる」穴は、注意書きを足すより、テスト・型・CI で検出できる形にすることを次の工程の候補に挙げる〔両氏〕t-wada「「人間が頑張る」ではなく…「仕組みで気づける」にしないとつらい」（AI 時代の TDD 2026-04）\n- 両氏の資料の偏り:
