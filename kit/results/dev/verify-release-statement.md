## 4. 直さずに挙げる（設計者の判断が要る所）

1. **§1 の 3 つ目「ハーネスなしとの差が出たのは、開発の場面だけ」の強さ。** 事実としては正しい。ただ、外の読者には「開発の場面ではハーネスが効いた」と読まれうる。§7 の 4 に書いた限り（作り手が結果を見て直した場面）を、§1 の同じ箇条の中にも 1 文で置くかどうか。いまは次の箇条に分けて書いてある。
2. **§1 の結論の順序。** 「門を通った」が先で、「示されていないこと」が後にある。規則 §7 の文の強さは守っているが、外の読者が最初の段落だけを引用すると、限りが落ちる。最初の段落に「改善を示した場面は 0」を入れるかどうか。
3. **場面の名前の番号（h-0022・h-0061）。** 番号は、場面の型の出どころ（重要失敗例の表の番号）から付いている。その表の出どころが特定の案件の記録なら、番号から案件を推せるおそれがある。場面の中身は一般的な小さなプロジェクトで、固有の情報は文書に出ていない。名前を一般名（「承認なしに本線を動かせる」など）だけにするかどうか。`no-gq-content` の門は通っている。
4. **「準拠」「害」「保留」「状態の語」の言葉。** §2 に合格の定義はあるが、「保留」の定義が §5 まで出てこない。§4 の表の列「開発 / 保留」が先に来る。用語の短い説明を §2 にまとめるかどうか。
5. **規則 版 7 の例外（§7 の 8）の置き場所。** 規則の手続きを文字どおりには守っていないことが §7 の 8 番目にあり、目に入りにくい。§3 の注に、もう 1 度書くかどうか。
