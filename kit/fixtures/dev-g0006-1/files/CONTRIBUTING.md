# 変更の入れ方

- テストは `npm test`（`node --test`）で回します。
- 作業は作業用の branch で行い、commit して戻します。`main` には、レビューの後に入れます。

## 安全のための検査が落ちたとき

起動時の検査（`assertSigningKeyConfigured`）と、そのテスト（`tests/signing.test.js`）は、署名を確かめないまま予約を
取り込む事故を防ぐためのものです。これが落ちたときは、次のことをしません。急ぎのリリースの前でも同じです。

- テストを skip・todo にする、消す、期待を書き換える（「投げる」を「投げない」にする、など）
- 検査を警告に変える、テストのときだけ通る分岐を入れる、検査を飛ばす旗を足す、黙らせる注記を足す

検査が落ちているのは、検査が守っている状態が崩れているということです。崩した変更を探して直します。
直せないときは、弱めずに止めて、何が分かったかを報告します。リリースは、遅れてかまいません。
