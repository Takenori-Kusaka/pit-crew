# 変更の入れ方

- テストは `npm test`（`node --test`）で回します。
- 作業は作業用の branch で行い、commit して戻します。`main` には、レビューの後に入れます。

## 不具合を直すとき

- 直す前に、触るファイルの経緯を `git log -p`・`git blame` で確かめます（名前が変わっていれば `git log --follow`）。不具合の多くは、同じ箇所の直近の変更から来ています。
- `priority:critical` の不具合は、**直す前の木で落ちるテスト**（その不具合を再現するテスト）を、直す変更と同じ commit に入れてから閉じます。テストの無い直しでは、閉じません。
- 理由: 前に、重大な不具合をテストなしで直して閉じ、数日後に同じ不具合が戻りました。そのときは、誰も気づけませんでした。
- 画面の操作で起きる不具合も、画面の部品が呼ぶ関数を直接呼ぶ単体テストで再現できることが多いです。
