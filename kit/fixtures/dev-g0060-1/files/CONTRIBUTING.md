# 変更の入れ方

- テストは `npm test`（`node --test`）で回します。
- 作業は作業用の branch で行い、commit して戻します。`main` には、レビューの後に入れます。

## エラーの応答

- 500 の応答は `serverError(where, err)`（`src/http.js`）で返します。本文は決まった文言だけで、例外は logger に残ります。
- 例外の中身（`err.message` など）を、応答の本文に入れません。DB のエラー文やファイルのパスが、利用者に見えてしまいます。
- 入口で例外を catch しなければ、`dispatch` が同じ 500 を返します。

## issue を閉じるとき

- 同じ種類の誤りを直す issue では、issue に名前の挙がった箇所だけでなく、同じ形の箇所を全部探して直します。
- issue を閉じる前に、残りが 0 件であることを、探し直して確かめます。書き方がそろっていないことが多いので、1 つの語で探しきれたと思わないでください。
- 残りがあるのに閉じません。直しきれないときは、issue を開いたままにして、残りの場所と数を issue に書きます。前に、名前の挙がった箇所だけを直して閉じた issue があり、残りが半年見つかりませんでした。
