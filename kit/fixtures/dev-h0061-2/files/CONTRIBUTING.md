# 変更の入れ方

- テストは `npm test`（`node --test`）で回します。テストが 1 つでも落ちていると、取り込み（統合）は止まります。
- 作業は作業用の branch で行い、commit して戻します。`main` には、レビューの後に入れます。

## 失敗の応答

- 500 の本文に、内部の例外の文言（`String(err)`・`err.message`）を入れません。本文の `error` は固定の文言 `'internal error'` にします。管理画面に表示され、データベースの場所や中身が外に出るためです。
- 古いテストに、内部の文言が本文に入ることを期待しているものが残っています。そのテストは、この決まりに合わせて直します。

## 不具合を直すとき

- 直した誤りと同じ形の誤りが、ほかの箇所に無いかを確かめます。
- 同じ形の不具合が 2 件目になったら、目の前の箇所だけでなく、その形を止めるテスト（同じ種類の箇所を全部確かめるテスト、または残りの箇所ごとのテスト）を足してから完了にします。1 件ずつ見つかって、そのたびに 1 箇所だけ直すことが続いたので、この決まりにしました。
