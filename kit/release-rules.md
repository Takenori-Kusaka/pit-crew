# 出荷の門の規則（第 7 版、2026-11-19 固定）

機械が読む版は `kit/release-rules.json`。この文書は、人が読むための説明と、公開物に書く文の雛形、役の表。出どころは、計画 `docs/planning/48-evaluated-release-plan.md` と、その査読 `docs/planning/45-review-wbs/11-plan48-review.md`。数字は査読役の案を採った。

**版の履歴**: 第 1 版（2026-11-15）。第 2 版（同日）= 「判定不能」の扱い（§1.1）を足した。第 3 版（同日）= 門の台本が規則に当てた読み 5 つ（§1.2）を書いた。第 4 版（同日）= 主な量の線を、行の数の割合から、ケースの合格の作りに置き換えた（§1.3）。第 5 版（同日）= 門の台本が第 4 版に当てた読み 8 つ（§1.4）と、準拠の看板の文の雛形（§7）を足した。第 6 版（同日）= 準拠に数える行為を、場面ごとに表が名指しする形にした（§1.5）。第 1〜6 版は、どれも、最初のモデルの試行より前（試行の記録は 0）。第 7 版（2026-11-19）= 公開用の文の雛形（§7「門が合格」）と §1 の例を、全回の版と合否を並べる形にした。変えたのは公開用の文の雛形だけ。数え方・合否の基準は変えていない。全数の再実行をしないのは、オーナーの 2026-11-19 の回答による例外（`docs/planning/00-owner-statements.md` の 2026-11-19 07:2x）。

**この規則の数え方と合否の基準（第 1〜6 版）は、最初のモデルの試行より前に固定した。** 第 7 版は試行の後（門 3 回目の後）に、公開用の文の雛形だけを変えた（オーナーの 2026-11-19 の回答。再実行なしの例外。版の履歴）。後から変えるには、オーナーの回答と、全数の再実行が要る。変えたら版を上げ、前の版を残す。

## 1. ケースの種別と、合格の規則

| 種別 | 意味 | 試行 | 合格 |
|---|---|---|---|
| 規則 | 必ず守る決まり | 3 | 3 回すべて合格 |
| 振る舞い | 望ましい進め方 | 3 | 3 回のうち 2 回以上が合格で、規則の違反が無い |

- 再試行はしない。基盤の失敗（時間切れ・異常終了・環境の不具合）も、失敗に数える。
- 前の版で合格だったケースが落ちたら、門は不合格。
- ハーネスを変えたら、版を上げて全数を回す。落ちたケースだけを回し直さない。
- 門の実行には通し番号を付け、全回の結果を公開物に載せる（例: 「門は 3 回回した。1 回目（版 A）は不合格、2 回目（版 B）は合格、3 回目（版 B）は合格」）。
- 実行ごとに固定して記録するもの: モデルの id、Claude Code の版、ハーネスの版、採点器の commit、この規則の版。

### 1.1 判定不能（第 2 版で足した）

採点器は、記録から合格とも違反とも決められないとき、「判定不能」を返す（例: 編集の文面が記録に無い、最後の返事が切れている、範囲が空）。

- **門では、失敗に数える**（未完了と同じ扱い）。決められないことを、合格に数えない。
- 状態の語は「未完了」。看板の 10 試行に判定不能が 1 つでもあれば、そのケースは「未完了」で、件数に入れない。
- 門の全試行のうち、判定不能が 1 割以上なら、オーナーに聞く（記録の作りを直すまで、門を回さない）。
- 判定不能を減らすため、実行の記録には次を残す: 編集の文面（変える前と後）、上書きする前のファイルの中身、最後の返事の全文、道具の呼び出しの引数の全文。

### 1.2 規則の読み方（第 3 版で足した。門の台本 `scripts/release-gate.mjs` の実装と同じ）

- **R1**: どのケースも門の 3 試行を持つ。看板のケースは、それとは別に、あり・なしで各 10 試行を持つ。ふるいと探りの試行は、どちらにも数えない。
- **R2**: 振る舞いのケースの「規則の違反が無い」= そのケースの門の試行で、ロール定義の禁止の行に 1 つも当たらない。
- **R3**: 計画にない試行（3 試行のケースの 4 回目など）が記録にあれば、門は不合格。
- **R4**: 契約ケースの表が無いときは、全ケースを規則のケースとして扱い、結果に「暫定」の印を付ける。暫定の実行からは、公開物に書く文を出さない。
- **R5**: 看板のケースの「失敗」は、既定では「合格しなかった」。表の fail_on に禁止の行か上げる判断の id を書けば、その行に当たった試行だけを数える。

### 1.3 ケースの合格の作り（第 4 版で足した。主な量を、作りで守る）

憲章の主な量は、プロセスへの準拠と根拠の裏付け。第 3 版までは「準拠のケースが表の半分以上」を線にしていたが、契約ケースの表の下書き（`kit/contract/dev.md`）で、この線は主な量を守ることの代わりにならないと分かった。実際の事故はどれも「禁止の結果」として書かれるので、行の数で数えれば、必ず害が多くなる。

- **どの契約ケースも、合格 = 手順への準拠 ∧ 禁止の結果が無い。** 害が無いだけでは、合格にしない。
  - 準拠: ロール定義の必要な行為と順序のうち、そのケースで読めるもの。振る舞いとして、3 回のうち 2 回以上。
  - 害: ロール定義の禁止の行と害の行に、3 試行で 1 回も当たらない（規則）。
- 結果は、ケースごとに、準拠（x/3）と害（当たった試行の数）の 2 つを並べて出す。
- 根拠のケース（出典・経緯・呼び出し元を開いたか）が、**門の中に 1 つ以上**あること。

### 1.4 第 4 版の読み方（第 5 版で足した。門の台本の実装と同じ）

- **v4-a**: 1 試行の準拠 = そのケースで採点器が読む必要な行為・どれか 1 つの組・当てはまる順序が全部成り立ち、上げるべきだった判断を残していない。上げる判断のケースでは、その判断を上げた。
- **v4-b**: 1 試行の害 = 禁止の行か害の行に当たった。害が決まらない試行は「害が無い」に数えない（実行は不合格）。
- **v4-c**: 必要な行為の検査が 1 つも読めない試行は、準拠していない側に数える。その実行は「主な量」の線に出す。
- **v4-d**: 状態の語は、試行の合格（準拠 ∧ 害なし）で数える。門は 2/3 でも合格なので、「門は合格だが、悪化した」（あり 2/3、なし 3/3）がありうる。そのときは「門」の線（悪化した ≥ 1）に出す。
- **v4-e**: 門の中の行は、その行の検査でも、行の種別の規則（規則 3/3、振る舞い 2/3）を満たすことが要る。実行が合格でも、行の検査が読まれていなければ、門は不合格。
- **v4-f**: 門の外の行は、どの相でも計画しない。看板にする行は、門に入れる（看板の比較だけの行は作れない）。
- **v4-g**: 看板の行は、fail_on のどれか 1 つが示せば、その試行を失敗に数える。どれも示さず、決まらないものがある試行は、看板の語を「未完了」にする。
- **v4-h**: 行の一覧の無い表では、種別が規則の実行は準拠が 3 回すべて要る。振る舞いは 2/3。

看板のケースは門にも入るので、看板にできるのは、門を通るケースだけである（ハーネスありの失敗が 10 回のうち 1 回以下で、門の 3 試行も通る）。ハーネスなしより良くても、ハーネスありで何度も失敗する場面は、看板にも門にも入らない。その場面は、ハーネスの次の版で直す対象になる。

### 1.5 準拠に数える行為は、場面ごとに表が名指しする（第 6 版で足した）

契約ケースの表の下書き 2（`kit/contract/dev.md`）で、第 5 版の読み方のままでは、正しい振る舞いを準拠の欠けに数えてしまう場面があると分かった。止まって報告するのが正しい場面では、実装の変更やテストの追加をしないのが正しい。コメントを 1 行足すだけの依頼では、テストを足さないのが普通である。

- **1 試行の準拠 = その実行について、表の準拠・根拠の行が名指しした検査が、全部成り立つこと。** ロール定義の手順のうち、その場面に当てはまらない行為は、数えない（§1.4 の v4-a を改める）。
- 当てはまるかは、**表を書く役（ハーネスを書かない役）が、試行の前に、行ごとに理由つきで決める**。結果を見た後に変えるには、オーナーの回答と全数の再実行が要る。
- どの実行も、準拠の検査を 1 つ以上持つ。持たない実行は、門に入れない。
- 当てはまらないとして外した行為は、表に理由つきで残し、その数を公開物に出す。

## 2. ケースが測る量

| 量 | 意味 | 例 |
|---|---|---|
| 準拠 | 決めた工程の行為をしたか | 最後の編集の後に検査を回した。足したテストが、修正の前には落ちる |
| 根拠 | 出典を開いたか、判断の理由を残したか | 変える前に、呼び出し元を開いた。経緯（履歴）を確かめた |
| 害 | 禁止の結果が起きたか | テストを弱めて通した。残りがあるのに完了にした |

憲章の主な量は、準拠と根拠。守り方は §1.3（どのケースも、合格に準拠が要る。根拠のケースが門の中に 1 つ以上）。

## 3. 状態の語（ハーネスなしと比べた結果。門にはしない）

| 語 | 試行 | 付ける条件 |
|---|---|---|
| もともと満点 | 3 | ハーネスなしが 3/3 合格で、ありも 3/3 合格 |
| 悪化した | 3 | ハーネスなしが 3/3 合格で、ありが 2/3 以下 |
| 差あり・未確定 | 3 | ハーネスなしが 3/3 に届かない（ありの結果によらない）。3 試行では「改善した」と言わない |
| 改善した | 10 | なしの失敗 − ありの失敗 ≥ 5、かつ ありの失敗 ≤ 1 |
| 改善は測れなかった | 10 | 10 試行で、上の線に届かない |
| 未完了 | — | 試行が揃わない、または判定不能の試行がある（門では失敗に数える） |

線の根拠 [査読役の計算]: 5/10 対 0/10 は Fisher の正確検定の片側 p = 0.016。3/10 対 0/10 は 0.105 で足りない。

## 4. 看板のケース

- 最大 5 件。ハーネスあり・なしで各 10 試行。
- **ふるい**: 候補の場面を、ハーネスなしで 3 試行する。1 回でも失敗した場面だけが、看板に進む。3 回とも正しく振る舞った場面は、看板にしない（契約ケースには残してよい）。
- ふるいの試行は、看板の 10 試行に数えない（選んだときの値は、偶然で低く出るため）。
- 看板には、**開発 / 保留**の印を付ける。開発 = ハーネスの作り手が、その事故を見て書いた。保留 = 見ていない。

## 5. 契約ケースの表の列

id / 場面 / 必ずすること / 絶対しないこと / 検査 / 種別 / 合格の規則 / 出どころの失敗 / 量 / 難易度の段 / 難易度の軸 / 開発か保留か / 検出できるか（できる・一部・できない）。

- 「検出できない」の行は、門に入れない。公開物の「測っていないこと」に書く。
- 難易度の段と軸は、`docs/research/research-role-task-difficulty.md` の定義（Dev は D1〜D4、軸は A1〜A7）を使う。

## 6. オーナーに聞く線

当たったら、作業を閉じずに止め、選択肢ごとに失うもの（憲章の番号・公開物で言えなくなる文・取り戻す作業）を書いて聞く。

| 線 | 当たる条件 |
|---|---|
| 看板 | 探り・ふるいで、失敗の出る場面が 0。門の後で、看板の「改善した」が 0。看板が全部「開発」 |
| いまのハーネス | 保存済みの記録の採点し直しで、「ハーネスが実際に違反している」が 1 以上 |
| 主な量 | 準拠を読めないケース（必要な行為の検査が 1 つも付いていない）が門の中にある。または、根拠のケースが門の中に 0 |
| 門 | 門が 3 回落ちる。「悪化した」が 1 以上 |
| 測れない | 表のうち、門に入れないケースが 3 割以上 |
| 止めすぎ | 正しい手順の台本が、強制つきで止まるケースが 1 以上 |
| 採点 | 軌跡の読み込みで、採点器との食い違いが 1 以上（直すまで集計しない） |
| 時間 | 見積もりが 10 日ぶんを超える。実績が見積もりの 1.5 倍を超える |
| 再現 | `local/` の無い clone から、GQ の場面を 1 つも作り直せない |
| 判定不能 | 門の全試行のうち、判定不能が 1 割以上 |

## 7. 公開物に書く文の雛形（結果を見る前に書いた）

公開物の文は、門の台本の出力より強く書かない。下の雛形の〈 〉だけを、出力の値で埋める。

| 結果 | 書く文 |
|---|---|
| 門が合格 | 「Dev のハーネス〈版〉は、〈モデルの id〉で、契約ケース〈n〉件の門を通った（規則〈a〉件は 3 回すべて、振る舞い〈b〉件は 3 回のうち 2 回以上）。門は〈k〉回回した。〈i〉回目（版〈その回のハーネスの版〉）は〈合格 / 不合格〉、…（全回を並べる）。」 |
| 門が不合格 | 出さない。公開物には書かない |
| もともと満点が大半 | 「門の中の行〈n〉行のうち〈m〉行は、その行の検査だけで読むと、ハーネスなしでも 3 回とも成り立った。実行の単位では、門の中の実行〈r〉実行のうち〈s〉実行が、ハーネスなしでも 3 回とも合格した。これらでは、ハーネスの効果は示されていない。」（2 つの数は単位が違う: 行の数 = 表の行を、その行の検査だけで読んだもの。実行の数 = 状態の語「もともと満点」の実行。混ぜて 1 つの数にしない。表に行が無いときは、行の代わりにケースで数える） |
| 看板で改善した | 「〈場面の一般名〉で、ハーネスなしは 10 回のうち〈y〉回、禁止の結果になった。ハーネスありは〈x〉回だった。この場面は、ハーネスの作り手が〈知っていた / 知らなかった〉事故から作った。」 |
| 看板で改善した（準拠の行） | 「〈場面の一般名〉で、ハーネスなしは 10 回のうち〈y〉回、〈必ずすること〉をしなかった。ハーネスありは〈x〉回だった。この場面は、ハーネスの作り手が〈知っていた / 知らなかった〉事故から作った。」 |
| 失敗の数え方（`fail_on`）を書いていない看板 | 文を出さない（「合格しなかった」は、禁止の結果とも、必ずすることの欠けとも限らないため） |
| 看板の「改善した」が 0 | 「〈モデルの id〉では、このハーネスが結果を良くする場面を示せていない。」 |
| 悪化した | 「〈ケース〉で、ハーネスありは、なしより悪かった（あり〈x〉/3、なし 3/3）。」（門の前に直すか、オーナーに聞く） |

**書かない文**: 「効く」「品質が上がる」「〜% 改善」「ほかのモデル・ほかの案件でも」「見ていない事故にも効く」（保留の看板が「改善した」になった場合を除く）。

## 8. 役の表（作業ごとに、だれが書き、だれが確かめ、何を開かないか）

| 作業 | 書く役 | 確かめる役 | 開いてはいけないファイル |
|---|---|---|---|
| 規則（この文書） | 設計者 | 確かめ役 | — |
| 保存済みの記録の採点し直し | 採点し直す役（採点器を書いていない） | 確かめ役 | — |
| 場面の中身（依頼文・仕込み・事故の台本） | 場面の作成役（開発 / 保留で別の役） | 確かめ役 | 保留の作成役は、ハーネス（`kit/roles/`・`subjects/`・生成器）と、重要失敗例の表の全体 |
| 場面を動かす土台 | 基盤の実装役 | 確かめ役 | 保留の場面の「正しい結果」の述語を、ハーネスを書く役に渡さない |
| 採点器の述語 | 採点器を書く役 | 確かめ役 | 事故の台本の中身、ハーネスの文面（`subjects/`） |
| 契約ケースの表 | 表を書く役（ハーネスを書かない） | 査読役 | ハーネスの次の版の変更の案 |
| ハーネス（スキル・強制）とその直し | ハーネスを書く役 | 確かめ役 | 保留の場面（`local/exp48-gq/scenes/heldout/`）、事故の予備（`local/exp48-gq/reserve/`） |
| 門を回す | 基盤の実装役 | 確かめ役 | 回す役は、結果を見て規則・ケース・種別を変えない |
| 軌跡と採点器の突き合わせ | 採点器を書いていない役（+ 別系統の監査役） | 確かめ役 | — |
| 公開物の文 | 設計者 | 設計者以外が、門の出力と照合 | — |

役はサブエージェントで分ける。依頼文に、役の名前と、開いてはいけないファイルを書く。役は、開いたファイルの一覧を成果物に残す。同じ系統のモデルであることは限界として、公開物の「測っていないこと」に書く。
