## 0. 結論（先に）

1. **今の measure は FRAME（Chan ら 2022）が言う「rationale-label consistency（RLC）」型で、採用案の文言そのものを理由として渡したとき最高点が出るのは、この型の定義どおりの挙動**（FRAME 公理 1「参照理由 = 予測ラベルそのものが最高点」）[一次]。欠陥ではなく、測りたいものと測度の型が合っていない。
2. **LAS（Hase ら 2020）の型は我々の設定では使えない。** LAS は「理由だけで予測できる点（漏れ k=1）」と「できない点（k=0）」に分けて平均するが、我々は最初から課題を伏せて理由だけで読ませているので全点が k=1 に入る。RORA（Jiang ら 2024）は「全理由が漏れると LAS は未定義」と明記 [一次]。昨夜の候補 (a)「LAS の型」[推論] は出典確認の結果、**型が違う**。
3. 測りたいのは **「結論を知った上で、理由が追加で運ぶ情報」** で、これは REV（Chen ら 2023）/ RORA の **条件付き V-information** 系の問い。ただし両者は評価器の学習を要し、かつ結論を含む基線に条件付けるだけでは漏れが残る（RORA の実測: REV で漏れ理由 0.147 > 人の理由 −0.038）[一次]。
4. 学習無しで近づける手は **(i) 結論語（全案の識別語）を伏せ字にし、(ii) 伏せた退化基線が対照に戻ることを点ごとに確かめ（LAS の k を「伏せ字の失敗」の検出に転用）、(iii) 「同じ課題の別の判断の点の理由」を対照に置いて課題語彙からの推測を差し引く** — 伏せ字は Believing without Seeing（2025）が exact-string で実施 [一次]、別入力の説明を対照にするのは ALMANACS / 反事実 simulatability の設計 [一次]、課題語彙の近道は Poché ら 2026 が実測 [一次]。
5. 提案する主測度（§4 候補 A）: **S = P(採用 | 伏せ字理由) − P(採用 | 同課題・別点の伏せ字理由)**、Jev の確率で計算、1 点 1 arm あたり Jev 16〜24 呼び出し（**0.001〜0.0015 ドル**）。副測度（候補 B）は local 8B の teacher-forced log p で同じ対比を取り、符号の見張りに使う（追加支出なし）。
6. 「言及 ≥1 の点に限る」（昨夜の候補 (a) 前半）は**不要かつ有害** [推論]: 伏せ字後は案を名指ししない理由も測れるし、名指しの有無で絞ると案を列挙する arm（default）だけが標本に残り比較が歪む。

## 1. 起きたことの再定式化 [推論]

読み手の選択率 P(採用 | 入力) を 3 つの入力で測った: 理由あり / 理由なし（対照）/ 退化基線（採用案の文言 1 行）。観測は 退化 1.00 ≫ 理由あり 0.58〜0.84 > 対照 0.45〜0.61。

これを分解すると、理由あり条件の上昇には 3 つの源がある。

| 源 | 何が読み手を動かすか | 今の統制 | 文献上の名前 |
|---|---|---|---|
| L1 結論の語の漏れ | 理由の中の採用案の名前・言い回しが案一覧の文言と一致する | `hideAdoption`（「採用」「chose」等の採否語だけ除去。案の名前は残る） | label leakage（Hase 2020 / RORA） |
| L2 課題からの推測 | 理由の課題語彙から「この種の課題ならこの案が普通」と読み手が自力で選ぶ | なし（課題文は渡していないが、理由文が課題を語る） | 読み手が課題を解く shortcut（Poché 2026 の B1、Pruthi 2022 の批判） |
| L3 理由の内容 | 観察・比較が、どの案の性質に合うかを示す | — | 測りたいもの |

対 対照の Δ は L1+L2+L3 の和。退化基線は L1 だけで 1.00 に届くので、理由あり − 退化基線 は負になる（天井）。**結論を含む条件に条件付けても、読み手が天井にいる限り差は出ない**（REV の構造を読み手に直接当てはめると潰れる理由。§2 REV 行の注）。

**文献から言えること（まとめ）** [推論 を含む]:
- 「理由だけを読ませ、ラベルを当てさせる」は RLC であり、結論の復唱で満点になるのは定義どおり（FRAME 公理 1）。L1 を切るには結論を**条件に入れる**（REV）か**消す**（RORA / 伏せ字）しかなく、読み手が天井にいる我々では条件に入れても差が出ないので、**消す**側。
- 消し方は、学習できるなら RORA（帰属で漏れトークン検出 + 反事実増強 + IRM）、できないなら exact-string 伏せ字（2025）。後者は言い換えを逃す。逃した分は **LAS の k の考え方（伏せた退化基線がまだ当たる点 = 伏せ字の失敗）で点ごとに検出**できる。
- L2（読み手が課題を解く）は Poché の B1 / Pruthi の批判に相当し、文献の統制は「別入力の説明を使う」（ALMANACS / 反事実 simulatability）か「事前知識で解けない課題」。我々は課題を植え込んでいるので、**同じ課題の別の判断の点の理由**を対照に置ける。
- 自明説明が対照に負けること（Pruthi の自明基線 = 対照）を**合格条件**として使うのは確立した作法。

## 4. 提案（RQ3）[推論]

### 4.1 入力の定義

判断の点 i（案 Oᵢ = {o₁…o_m}、m = 2〜5、採用 a、理由文 rᵢ、同じ run の別の点 j≠i の理由 rⱼ）。

- **mask(t)**: 文 t から **全案の識別語**（評価側がセル設計時に案ごとに登録する名詞句の一覧。採用案だけでなく全案）と `hideAdoption` の採否語を、**全案共通の 1 つの伏せ字**「[案]」に置換（案ごとに別の伏せ字を割り当てると、それ自体が写像を作る — Poché の匿名化漏れ）。第 2 段として、案一覧の文との文単位の埋め込み類似度が閾値を超える文を伏せる（言い換え対策、閾値は合成検証で決める）。
- **deg_i**: 採用案の文言 1 行（今の退化基線）。**mask(deg_i)** は構成上ほぼ空になる。
- 案一覧は今どおり伏せ字無しで、ラベルは呼び出しごとに入れ替え。

### 4.2 候補 A（主測度、Jev）: 別点対照つき伏せ字 simulatability

4 条件の採用案選択確率を各 k 通りのラベル順で平均する。

```
P_r   = P(採用 | mask(r_i), O_i)          理由あり（伏せ字）
P_x   = P(採用 | mask(r_j), O_i)          同課題・別点の理由（伏せ字）= L2 の推定
P_0   = P(採用 | 理由なし, O_i)            = ラベル位置・案文言の事前
P_d   = P(採用 | mask(deg_i), O_i)         伏せた退化基線 = 伏せ字の失敗検出

S_i   = P_r − P_x                          communicable（L3 の推定）
L1_i  = P_d − P_0                          結論語の漏れ残り（伏せ字後）
L2_i  = P_x − P_0                          課題語彙からの推測
k_i   = 1[L1_i > τ]                        τ は合成検証で決める（目安 0.15、m=2 では 0.5 の天井に注意）
```

- **点ごとの「漏れている」の定義**: k_i = 1（伏せ字が結論語を消し切れていない点）。LAS に倣い k=0 群と k=1 群を別々に報告し、arm 比較は k=0 群で行う。k=1 群の比率そのものが伏せ字器の品質指標。
- L2_i が大きい点は「読み手が課題を解いている」点として別掲（Poché の B1 相当）。S はこれを差し引いた量なので除外は不要。
- P_0 と P_d は案一覧と採用案だけで決まるので **arm 間で共有**できる（4 arm なら呼び出しが 1/4 に）。
- 読み方: arm ごとの S の中央値と符号検定（>0 の点の割合）、bootstrap CI。k=0 群の N を併記。
- 「言及 ≥1 に限る」はしない（§0 6）。伏せ字後に理由文がほぼ空になる点は S ≈ 0 が正しい判定（伝わる内容が無い）。

### 4.3 候補 B（副測度、local 8B、teacher-forced）: 案条件付き尤度の対比

読み手の生成も Choice も使わず、既存の `logprob.py` の mean log p と同じ経路で計算する。

```
ℓ_i(o)  = mean log p( mask(r_i) | "候補: O_i（伏せ字無し）。著者は o を選んだ。著者の理由:" )   各案 o
S^B_i   = ℓ_i(a) − mean_{o≠a} ℓ_i(o)                採用案を前提にした方が理由が尤もらしいか
X^B_i   = 同じ式を mask(r_j) で                        別点対照（≈0 であるべき）
```

- 前提文に課題文は入れない（L2 を増やさない）。案一覧は全条件で共通なので差分で相殺する。
- 符号の見張り（S と S^B の符号一致率）と、Jev が使えない環境の代替。連続量なので引き分けが出ない（local 8B の Choice で引き分け 15/30 だった問題の回避）。
- 弱点: mean log p は文長に鈍く、理由が長いと差が薄まる。合成検証で S^B の分離が出ない場合は候補 A だけで進める。

### 4.4 構成による両方向の検証（人のラベル無し）

合成理由を 1 点につき次の 5 種作り、各 20〜30 点（既存 heldout-s5 / d3 の 28 点 + 合成）で下の期待を全部満たすことを合格条件にする。

| 合成理由 | 期待 | 検出する欠陥 |
|---|---|---|
| T1 結論の復唱だけ（deg_i、言い回し 3 通り） | S ≈ 0、L1 ≤ τ（k=0） | 伏せ字が効くか。言い換え版で k=1 が出る割合 = 伏せ字器の取りこぼし率 |
| T2 決め手の観察 1 文（案を名指ししない。例「既存の試験が移行無しでは落ちる」） | S > 0（m=2 で ≥0.3、m≥3 で ≥0.2 を目安） | 読み手が内容→案の対応を取れるか。案の記述が互いに区別できる性質を持つことが前提（セル設計への要件） |
| T3 T2 + 採用案の名指し | S ≈ T2 の S（名指しで増えない） | 伏せ字が名指しを消し、内容だけが残る |
| T4 別点 j の理由（同課題） | S ≈ 0 | 対照の妥当性（これが 0 でないと L2 の推定が壊れている） |
| T5 反対向きの決め手（却下案を支える観察） | S < 0 | 符号が内容に従う（RQ が負になり得るのと同じ） |

- 失敗の読み方: T1 で S > 0 → 伏せ字の取りこぼし（第 2 段の文単位伏せ字を強める）。T2 で S ≈ 0 → 読み手が内容と案を結べない（案記述が抽象的すぎる = セル側）。T4 で S > 0 → 別点の理由に i の案の話が混ざっている（別 run の同点の理由に替える）。
- 実文 77 点では、まず k=1 の比率と L2 の分布を見る。設計書 23 §12 の学び（合成で通って実文で崩れた抽出器）と同じ罠なので、**合成合格 → 実文の分布確認 → 判定に使う** の順を崩さない。

## 5. 費用（RQ4）[推論]

Jev: 0.042 ドル / 1M 入力トークン、1 呼び出し約 1,500 トークン → **1 呼び出し 0.000063 ドル**。

| 候補 | 1 点 1 arm の呼び出し | トークン | ドル / 点 | 77 点 | 400 点 |
|---|---|---|---|---|---|
| A（k=4、4 条件） | 16 | 24k | 0.0010 | 0.08 | 0.40 |
| A（k=6、4 条件） | 24 | 36k | 0.0015 | 0.12 | 0.60 |
| A（P_0, P_d を 4 arm で共有、k=4） | 8 + 8/4 = 10 | 15k | 0.0006 | 0.05 | 0.25 |
| B（local 8B） | teacher-forced 2m 回（m=2〜5 → 4〜10 回、生成なし） | 1 回 約 500 トークンの prompt eval | 0（GPU 時間）。CPU なら 1 回 約 4.5 秒（§12 の 272 秒 / 60 回から）→ 1 点 20〜45 秒、GPU は 1 桁速い | — | — |

昨夜の実測（Jev 読み手 77 点 × 3 条件 × k で 485k トークン = 0.02 ドル）と整合する桁。候補 A は条件が 1 つ増えるだけなので **1 arm 20 点 × 4 arm で 0.1 ドル未満**。

## 6. 限界・未確認

- 伏せ字は言い換えを逃す（2025 論文も exact-string のみ）。k_i で点ごとに検出し、群分けで隔離する設計だが、k=1 群が大きい arm は比較から脱落する。第 2 段（文単位の埋め込み伏せ字）の閾値は未決定。
- L2 の対照「別点の理由」は、同じ run 内の点同士で話題が重なると過大（S が過小）になる。別 run の同点理由を代替にできるが、arm 間で著者の文体が揃わない。
- Jev は確率を返すが較正の独立検証が無い（`research-typesafe.md`）。本提案は確率の**差**しか使わないので較正の線形歪みには鈍いが、順序の歪みには弱い。local 8B との符号一致で見張る（現状 14/15、引き分け除く）。
- 読み手が案の内容を理解して結べるか（T2）は、植え込んだ案の記述の具体性に依存する。これは測度の限界ではなくセル設計への要件だが、既存 heldout-s5 / d3 の案記述がそれを満たすかは未確認。
- 2024–2026 の無ラベル評価 3 本は要旨しか読んでいない。設計書に写す数値は無い。
- 本文を読めなかった出典: Treviso & Martins 2020 https://arxiv.org/abs/2004.13876（Pruthi 経由 [二次]）。REV が結論を含む b に条件付けて 1.14 対 0.26 の分離を出せた機構（評価器の fine-tune による）は本文で読んだが、我々の「学習無しの読み手」で同じ分離が出ないと言う §1 の推論は実測していない（昨夜の退化 1.00 がその傍証）。
