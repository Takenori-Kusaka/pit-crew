# 共通の指示（台帳づくり。research-practice-gap の Part 1 用）

リポジトリ: E:\Github\pit-crew（Git Bash で /e/Github/pit-crew）。巨大なので `runs/` は走査しない。
読んではいけないもの（セルの中身）: `experiments/**/cells*.mjs`、fixtures、verdicts、`suites/*/suite.yaml`。必要ない。
変更してよいのは、自分に割り当てられた出力ファイル 1 つだけ（`docs/research/_scratch-practice-gap/ledger-<記号>.md`）。commit しない。モデル実行・Harbor 実行はしない。

## 背景
このプロジェクトは 2026-10-31〜11-11 に `docs/research/` で調査を行い、その後に多数の実験をした。2026-11-12 に「評価の実施が自分たちの調査に従っていなかった」ことが露見した。
あなたの仕事は、割り当てられた調査ファイルから「どう評価するか」についての具体的な推奨を 1 行ずつ抜き出し、それぞれがその後どう扱われたかを証拠つきで判定すること。

## 手順
1. 割り当てられた調査ファイルを全文読む（Read。行番号つき）。
2. 評価の方法（課題・セルの作り方、採点器・述語・judge の検証、統計・回数・止め方、実験の手順、比べる相手、報告で言ってよいこと、レビュー・前提の点検）に関する **具体的な推奨** を全部抜き出す。「X を Y の前にする」「セルは…でなければならない」「採点器は…」「…と主張しない」の形のもの。ロールの仕事の中身（ハーネスの規定そのもの）は対象外。文献の単なる紹介も対象外（「pit-crew への示唆」「提案」「推奨」「やめるべき主張」の節が主だが、本文中の推奨も拾う）。1 推奨 1 行。同じファイル内で重複する推奨は 1 行にまとめ行番号を並べる。
3. 各推奨について、その後の扱いを次から探す: `docs/planning/*.md`、`docs/experiments/EXP-*.md`、`docs/log/*.md`、必要なら `experiments/**/README.md` と `experiments/**/*.mjs` のファイル名（中身はセル以外なら grep 可）、`evals/`・`scripts/` の存在確認。grep（日本語と英語の鍵語の両方）で探し、当たった箇所は前後を読んで確かめる。
4. 状態を次の 5 つから 1 つ選ぶ:
   - `常設` = 常設の規則・仕組みとして採用された（憲章 00-goal-charter の規律、設計書・評価計画の規則、テンプレート、lint、採点器の test など、**以後の実験すべてに掛かる場所** にある）。どこにあるかを file:line で。さらに「その規則が 11-11〜11-12 の fix の段（計画 31、EXP-44〜47）でも実際に守られたか」が分かれば書く（守られた / 規則はあるが守られなかった / 不明）。
   - `一度` = 一度実施された（特定の実験や段で）が、常設の規則にはならず、後の段（QM: 計画 27・EXP-41〜43、fix: 計画 31・EXP-44〜47）では行われていない／確認できない。
   - `提案のみ` = 計画文書・ログに案や「次にやること」として書かれたが、実施の証拠がない。
   - `言及なし` = 調査ファイルの外で二度と出てこない（grep で 0 件、または調査ファイルへの参照だけ）。
   - `未確認` = どちらとも決める証拠が見つからなかった。**推測で埋めない。**
5. 日付を付ける（推奨が書かれた日 = 調査ファイルの日付、採用・実施・最後に言及された日）。

## 出力（Write で 1 ファイル）
先頭に: 読んだファイルと行数、使った grep の鍵語の一覧、状態ごとの件数。
本体は Markdown の表。列:
`ID | 推奨（平易な日本語 1〜2 文） | 出典 file:行 | 原文の引用（30〜80 字、そのまま） | 状態 | 証拠 file:行 と引用（そのまま。言及なしの場合は試した鍵語） | 日付 | fix の段で守られたか`
- ID は `<記号>-01` から。
- 引用は必ず原文そのまま。行番号は実際に Read / grep -n で確かめた値。確かめていない行番号を書かない。
- 判定に迷う行は末尾の「迷った行」に理由を書く。
- 最後の返信は 10 行以内: 出力ファイルの絶対パス、行数、状態ごとの件数、気づいた決定的な点 3 つまで（file:行つき）。
