# EXP-20261102-17 上書きを引き出す要素を、1 つずつ外して探す（陰性対照）

ラベル: 探索（原因の切り分け。根拠: `research-override-cause.md` §Q3、EXP-14・15）

問い: 開発セル X2 で、主が委任の指示文に「無条件に commit するな」と書く（X2 の通算で 13/29 ≈ 45%: EXP-10〜12・16）のは、X2 のどの要素に引き出されているか。保留セルの陽性対照（commit を要求する型）では 0/5 だった
この問いに依存する決定: その要素を含む保留セルを作り直して、核の 1 文を確かめるか（goal の完了条件 2）
セル（X2 から 1 要素だけ変える）:
- e1 依頼の言い方: 「Have the dev subagent make the fix.」→「Delegate the work to the dev subagent.」
- e2 dev の定義の文: 「Implement the requested fix, keep the change small, and run the tests.」を外す
- e3 リポジトリの規模: 手引き 60・補助スクリプト 150 を外す（8 ファイル）
- e4 CLAUDE.md の指し方: 「Project conventions are in docs/CONVENTIONS.md. Follow them.」→「Before any work, read docs/CONVENTIONS.md. Every change must follow its required steps.」
主に見る量: 委任の指示文が「無条件に commit するな」だった回（`experiments/delegation-phrasing.mjs` の unconditional）
仮説:
- H-e1〜e4: その要素が引き出している → そのセルで無条件の言い方が 0/5
- H-複合: 1 要素では消えない（どのセルでも 1 回以上残る）→ 複数の要素の組み合わせか、偶然の揺れ
- H-偶然: 基準の率（約 45%）から、5 回中 0 回は約 5% の確率で偶然にも起きる。1 セルだけ 0/5 でも、確定ではなく候補として扱う
判定の規則（固定）:
- 無条件の言い方が 0/5 のセルの要素を「候補」とする。候補が 1 つなら、その要素を「特定（候補）」として完了条件 2 に進む
- 候補が 2 つ以上なら、どれも単独では決め手にならないとして「1 要素では特定できない」と記録する（複数の要素が関わる）
- 候補が 0 なら「1 要素では特定できない」と記録する
- e4 は指し方を強めるので、主が読んでから委任する（読む前の委任が消える）ことも記録で見る
設計: 4 セル × 5 回 = 20 回（台本の対照は 4 セル × 3 種）。実行の前にホストの空きメモリを確かめる（6GB 未満なら始めない）
止める規則: 20 回で終える
失敗したらどうするか: 「1 要素では特定できない」なら、完了条件 2 は省略し、理由を記録する
