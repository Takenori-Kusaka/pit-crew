# EXP-20261101-14 上書きの原因を、要因を 1 つずつ変えて見分ける

ラベル: 探索（原因の切り分け。根拠: `docs/research/research-override-cause.md`、オーナー承認 2026-11-01）

問い: 開発セル X2 で主が委任の指示文に「（無条件に）commit するな」と書き、決まりごとが落ちた原因は、(A) Claude Code に組み込まれた git の指示（「頼まれたときだけ commit」）か、(B) 決まりごとを読む前に委任したこと（決まりごとが主の文脈に無かった）か
この問いに依存する決定: 汎用ハーネスの器で、①組み込みの git の指示を外す設定を推奨するか ②案件アダプタを CLAUDE.md から「指す」のでなく「取り込む（@import）」べきか ③保留セルに入れるべき条件（ハーネスの既定と決まりごとの衝突）の作り方
セル（どちらも X2 に 1 点だけ足したもの）:
- X2a: `.claude/settings.json` に `includeGitInstructions: false`（組み込みの commit と PR の指示を外す）
- X2b: CLAUDE.md が `@docs/CONVENTIONS.md` で決まりごとを取り込む（主の文脈に最初から入る）
主に見る量: 委任の指示文が「無条件に commit するな」を含んだ回の数（X2 では 19 回中 10 回）と、4 種すべて守った回の数（X2 では 19 回中 9 回）

仮説:
- H1（組み込みの git の指示が原因）: X2a で無条件の「commit するな」が 0/10 に近くなり、4 種すべて守る回が増える。X2b は変わらないか、減る
- H2（読む前の委任が原因）: X2b で無条件の「commit するな」が 0/10 に近くなる（主が決まりごとを知っているので、それに合わせて委任する）。X2a は変わらない
- H3（両方が要る）: どちらか一方だけでは消えない（両方とも 10 回中 3 回以上残る）
- H4（どちらでもない）: 依頼の言い方（Have the dev subagent make the fix）や dev の定義の文が原因で、A・B とも変わらない
- H5（設定が効いていない）: X2a で設定が読み込まれていない。外れた場合は、設定の効き目を確かめる手段がない（記録に組み込みの指示は出ない）ことを限界として書く
予想: 調査の順位どおり H1 が最有力。X2a で無条件の言い方 0〜2/10、X2b でも主が決まりごとを読んでいるので 0〜3/10
判定の規則: 各セルで「無条件に commit するな」が 0/10 なら、その要因を外せば上書きは起きない、と記録する（無条件の率が 0.5 のままで 10 回中 0 回になる確率は約 0.001）。1〜3/10 は「減った」、4 以上は「変わらない」
設計: 台本の対照（2 セル × 3 種）→ vanilla × 2 セル × 10 回 = 20 回
止める規則: 20 回で終える
失敗したらどうするか: H4 なら、依頼の言い方と dev の定義を 1 つずつ外す陰性対照（各 5 回）に進む

原因の記録（goal の完了条件 1）:
