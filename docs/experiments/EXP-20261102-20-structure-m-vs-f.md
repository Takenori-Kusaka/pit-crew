# EXP-20261102-20 構造の比較（本実行）: 混合（M）対 フラット（F）

ラベル: 確認（計画 13 の主の比較 H1）。前提: EXP-19（骨組み）で量が取れることを確かめた
問い: 同じ中身の Dev 工程定義を、混合（核に工程の表と入る / 出る条件、工程の中身は工程ごとのファイルを入るときに読む、工程は状態ファイルと成果物で判定）で渡すと、フラット（1 ファイルに全工程を 1 列）で渡すより、工程の取りこぼしが少ないか
この問いに依存する決定: SKILL.md を書くときの既定の構造（計画 13）
条件:
- arm: `path:subjects/dev-structure/M@/dev` と `path:subjects/dev-structure/F@/dev`（中身は 11 第 2 版。check-arms で同一性を確認済み）
- 課題: `suites/structure` の `t1-parallel-start`（同じ不具合が 3 か所）と `t2-rename-start`（チケットの後に名前が変わったファイル）。主の判定は 2 課題を合わせて行う
- モデル: claude-sonnet-5-5。各 arm × 各課題 10 回（arm ごとに計 20 回、全体 40 回）。中身は 11 第 2 版（commit 17d6605 の arm、check-arms で同一性確認済み）
- 副の条件（圧縮）: `t1-parallel-compact`（自動圧縮の窓を 100,000 トークン・50% にして途中で圧縮を起こす。compact-probe で F 4 回・M 1 回起きることを確かめた）で各 arm 5 回。主の判定には入れない
主の量（実行前に固定）: 工程の取りこぼし = 実装の編集（bin/・lib/ の変更）が、変更計画（notes/<ID>.md の作成）または テスト（tests/ の作成）より前に起きた試行（`phase-metrics.mjs` の skippedMemo または skippedTest）。少ないほど良い
判定の規則: 2 課題を合わせた arm ごと 20 回（故障を除く）で、M の取りこぼしの率 − F の率の差の Newcombe 95% 区間と、Fisher の正確確率（両側）。**区間の上限が 0 より小さく、かつ p < 0.05 なら「M は F より取りこぼしが少ない（この課題・このモデルで）」**。区間が 0 をまたげば「差は確かめられない」
副の量: 状態の述語（memo・failing-first・verify・commit・task）の全部守った率、文脈の最大の大きさ、工程の中身を読んだ回数
仮説: H1（M が少ない）/ 対立: 差がない（構造より中身が効く）/ F が少ない（全部見えているので飛ばさない）/ 天井（両方 0）
止める規則: 各 arm で決めた回数で終える。途中で結果を見ない。7 日枠 0.99 で止める。故障（invalid）は除いて件数を書く
実行の前に確かめること: 台本の対照（4 種 × 3 課題）が作ったとおり / ホストの空きメモリ 6GB 以上 / 7 日枠の使用率（2026-11-02 08:30 時点 0.72）
記録すること: 試行ごとの取りこぼし・状態の述語・工程の中身を読んだ回数・文脈の最大・圧縮の回数・軌道の判定（記録の「軌道 T?」）

| arm | 取りこぼし（変更計画またはテストより前に実装） | 全部守った（最終状態） | 文脈の最大（平均） | 工程の中身を読んだ回数 |

**読み方の注意**

## 追記: 故障判定の確認と計算し直し（2026-11-02、EXP-21 の前。モデルは呼んでいない）

EXP-19・20 で故障（invalid）とした 11 試行の記録をすべて読んだ。**どれも実行環境の故障ではなかった**。

| 判定していた種類 | 回数 | 記録で確かめた中身 | 直した判定 |
|---|---|---|---|
| `tool-unavailable`（exit 126） | 7 | すべて、エージェントが課題のファイル `bin/price`・`bin/checkout` を `bash` を付けずに直接実行し、`Permission denied` になったもの。課題のファイルには実行権限が無い（課題の README・テストは `bash bin/price` で呼ぶ）。7 回とも、その後エージェントは自分で回復して課題を解き、commit まで終えていた | `not-executable`（suspect: 残して数え、件数を書く） |
| 実行環境の異常終了（exit 1） | 1 | Haiku M（EXP-19）。Claude Code の最後の結果が `error_max_turns`（手数の上限 12）。最終状態は全部守っていた | `turn-limit`（suspect） |
| 実行環境の異常終了（exit 1） | 3 | 圧縮の条件（EXP-20 副）。Claude Code の最後の結果が「Autocompact is thrashing」（窓 10 万・50% で圧縮が空回りして止まった） | `compact-thrash`（suspect） |

- 直し方: pit-wall `validity.mjs` に 3 つの種類を足した。exit 126 は、相対パス（課題のファイル）の `Permission denied` のときだけ `not-executable` とし、システムのパスや「command not found」「bad interpreter」は従来どおり故障（invalid）のまま。異常終了は、Harbor の記録からエージェント自身の最後の結果（`agentStop`）を読み、手数の上限と圧縮の空回りだけを分けた。どちらも実際の記録の文字列でテストを足した（`test/validity.test.mjs`）
- 課題のファイルの実行権限は直さない。直すと課題の digest が変わり、EXP-20 の結果を EXP-21 で再利用できなくなるため。実行権限が無いことは両 arm で同じ条件で、回復に 1 手かかるだけである [推論: 手数の上限 12 に近い試行では効きうる。turn-limit は 1/100 回ほど]
- `regrade` で 4 つの run を保存済みの記録から計算し直した

**計算し直した主の判定（exp20-main、故障 0）**

## 追記 2: 測り方の不具合（EXP-21 で発見、2026-11-02）
