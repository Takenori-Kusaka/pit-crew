# EXP-20261101-02 役割の規則は、汎用の核と案件アダプタに分けられるか（前提 P1）

ラベル: 探索

問い: がんばりクエストの役割ハーネス（v0）の規則を 1 つずつ見たとき、どの案件でも使える部分と、この案件だけの部分に分けられるか
この問いに依存する決定: 目標を「汎用の核＋案件アダプタ」のまま進めるか、「案件ごとに作るための手引きと評価基盤」に縮めるか（08 §3 の方向転換の条件）

材料: `subjects/ganbari-quest-v0` の skills 5・agents 5 を、段落・箇条・表の行・コードの塊で 486 単位に機械的に分けたもの（`experiments/exp02/units.json`、`split.mjs`）
分類（各単位に 1 つ）:
- C 核: どのソフトウェア案件の同じ役割にもそのまま当てはまる（案件の固有の事実を含まない）
- P 引数つきの核: 規則は汎用だが、案件の値（ラベル名・パス・コマンド・ファイル名）を含む。値を引数に置き換えれば核になる
- A 案件のみ: この案件（製品・チーム・履歴）でしか意味がない
- X 分けられない: 規則と案件の事実が絡み合っていて、C / P / A のどれとも言えない

主仮説 H1（P1 は成り立つ）: X が 20% 以下、C+P が 50% 以上、2 体の一致（Cohen の κ）が 0.6 以上
対立仮説:
- H2（大半が案件のもの）: A が 50% 以上。汎用化できるのは一部だけ
- H3（絡み合い）: X が 40% 以上。分けようとすると規則が壊れる
- H4（測定の作り物）: κ が 0.4 未満。分類の定義があいまいで、この試験では何も言えない
- H5（単位の切り方の作り物）: 単位が細かすぎ・粗すぎて判定できない（「判定不能」の理由が単位の形に集中する）

予想:
| 仮説 | 数字 |
|---|---|
| H1 | X ≤ 20%、C+P ≥ 50%、κ ≥ 0.6 |
| H2 | A ≥ 50% |
| H3 | X ≥ 40% |
| H4 | κ < 0.4 |

反証の条件: X ≥ 40% または A ≥ 50%（κ ≥ 0.4 のとき）なら H1 を捨てる
この試験が H1 を落とせる理由: 分類者は H1 を知らされず、486 単位すべてを独立に分類する。v0 は案件の事実が多く混ざっている（調査 5-3）ので、H1 が誤りなら A・X が多く出る
設計: 文脈を持たない分類者 2 体（同じ定義と単位だけを渡す。互いの結果は見せない）。モデルは claude-sonnet 系（同じ系統なので偏りは相関する。限界として書く）。設計者は分類しない
使う方法と偏りの向き: 2 体の分類（同じ系統）＋不一致の単位を設計者が読む（分類はしない、理由を読むだけ）
止める規則: 1 回で終える。κ < 0.4 なら定義を直して 1 回だけやり直す（やり直しは探索として記録）
失敗したらどうするか: H2・H3 が残れば、08 §3 の方向転換の条件に当たるのでオーナーに報告する。H4・H5 なら定義か単位を直す

---（実行後）

結果（`experiments/exp02/agreement.json`）:

| | C 核 | P 引数つきの核 | A 案件のみ | X 分けられない |
|---|---|---|---|---|
| 分類者 A | 95（19.5%） | 327（67.3%） | 64（13.2%） | 0（0%） |
| 分類者 B | 101（20.8%） | 319（65.6%） | 62（12.8%） | 4（0.8%） |

- 一致率 84.8%、Cohen の κ = 0.70。不一致 74 件の多くは C と P の境目（23 + 17 件）と P と A の境目（15 + 15 件）。X をめぐる不一致は 4 件
- ファイル別: スキル（受信箱の手順が中心）は大半が P、案件のみ（A）はエージェント定義（dev-session 18、audit-manager 17、po-session 10）に多い
計画からのずれ:
- **分類者 B は「既定を P とし、C・A・X に当たる番号だけを 100 件ずつ列挙する」方法で分類した**（`experiments/exp02/b/spec.js`、理由の文は 4 種類だけ）。全単位を 1 つずつ判定した分類者 A（理由の文 397 種類）と方法が違う。B は P に寄りやすい（見落とした単位が P になる）。それでも A と 85% 一致した
妥当性:
- 構成概念: 「P = 値を引数に置き換えれば核になる」は分類者の判断で、実際に置き換えて動くかは確かめていない。P が多いことは「分けられる」の必要条件で、十分条件ではない
- 内的: 2 体とも同じ系統（Sonnet）で、偏りは相関する。B の方法の偏り（既定 P）
- 外的: がんばりクエスト 1 案件のハーネスだけ
- 結論: κ = 0.70 で、X ≤ 1%、A ≈ 13% という数字は 2 体で揃っている
解釈:
- **H1 は反証されなかった**（X ≤ 20%、C+P ≈ 87%、κ ≥ 0.6 をすべて満たす）。H2（A ≥ 50%）、H3（X ≥ 40%）、H4（κ < 0.4）はいずれも当たらなかった
- ただし主な部分は C（20%）ではなく P（66%）。つまり v0 の規則の大半は「汎用の規則に案件の値が埋め込まれた形」で、汎用化の作業の中心は**値を引数に出すこと**になる。これは調査（スキルを取り込んだ人が最も多く書き換えたのは説明文と道具の付け替え）と同じ向き [事後]
- この試験が示したのは「分けられそうに見える」まで。実際に分けて（v1）、同じセルで振る舞いが保たれるかで確かめる必要がある
状態: 終了。08 §3 の方向転換の条件（X が大半）には当たらない。次: v1 を作るときは、P の単位を「規則＋引数」に書き分け、引数の一覧をアダプタの項目にする
