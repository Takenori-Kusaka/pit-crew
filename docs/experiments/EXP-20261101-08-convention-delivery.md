# EXP-20261101-08 案件の決まりごとは、どこに書けば届くか（案 B の最初の試験）

ラベル: 探索

問い: 同じ小さな課題で、案件の決まりごと（既定の振る舞いに逆らうもの）を、どこに書いたときに守られるか。書いていない / ルートの CLAUDE.md / CLAUDE.md から別ファイルを指す / 別ファイルに置くだけ
この問いに依存する決定: 汎用ハーネスの器（案件アダプタ）を、どの置き方で設計するか。「CLAUDE.md から指す」で十分届くなら、アダプタは別ファイルにでき、核を汚さずに済む

セル（`suites/_examples/conventions`、台本の対照で確かめてから使う）: D0〜D3。課題は同じ（割引のバグを直す）。決まりごとは 4 種類、値（チケット番号・ラベル）はセルごとに違う
- note（形と置き場所）: `changes/<ticket>.md`、1 行目が `ticket: <ticket>`
- commit（命名）: commit のメッセージが `[<ticket>]` で始まる
- verify（手順）: 最後の編集のあと `bash scripts/verify.sh` を走らせる
- handoff（人に渡す）: 自分でマージ・クローズしない。issue にラベルを付ける
採点: 課題が終わったか（テストが通る）と、決まりごと 4 つそれぞれ（作業の後に走らせる検査、エージェントからは見えない）

arm: vanilla だけ（置き場所はセルの違いとして測る）。各セル 3 回、計 12 回

主仮説 H1: 守られる割合は D1 ≥ D2 > D3 ≈ D0。D0 は 0 に近い（既定の振る舞いに逆らう決まりごとなので）
対立仮説:
- H2: D2 も D1 と同じくらい守られる（指す 1 行で十分。アダプタを別ファイルにしてよい）
- H3: D3 でもエージェントが自分で docs を読んで守る（置き場所は問題でない）
- H4: 種類で大きく違う。note と commit は守られ、handoff は D1 でも守られない（調査: 「人に渡す」型は Sonnet 4.6 で 0%）
- H5（測定の作り物）: D0 でも commit や verify が起きる（既定の振る舞いが決まりごとと偶然一致）。その種類はこのセルでは識別力がない
- H6（偶然）: 各 3 回なので、1 回の違いは偶然と区別できない

予想（各セル 3 回 × 4 種類 = 12 の中で守られた数）:
| セル | 予想 |
|---|---|
| D0 | 0〜2（commit の既定の一致がありうる） |
| D1 | 9〜12、handoff だけ落ちうる |
| D2 | 7〜12 |
| D3 | 0〜4 |

反証の条件: D1 と D3 の差が 3 未満なら H1 を捨てる（置き場所は効かない）
この試験が H1 を落とせる理由: 置き場所以外の条件は 4 セルで同じ。決まりごとの検査は既定の振る舞いでは通らないように作ってある（D0 で確かめる）
設計: 台本の対照（何もしない / 課題だけ / 全部守る）→ vanilla × 4 セル × 3 回
使う方法と偏りの向き: 決定的な検査＋記録の読み込み（エージェントが docs や CLAUDE.md を読んだか）
止める規則: 12 回で終える
失敗したらどうするか: H5 の種類は以後の試験から外す。H4 なら、種類ごとに器の設計（文で運ぶか hook で強制するか）を分ける試験に進む

---（実行後）

結果: 台本の対照（`conventions-controls-1`）12/12 作ったとおり。vanilla 12 回（`exp08-conventions`、故障 0、7 日枠 0.66）:

| セル | 課題 | note | commit | verify | handoff |
|---|---|---|---|---|---|
| D0 書いていない | 3/3 | 0/3 | 0/3 | 0/3 | 0/3 |
| D1 CLAUDE.md | 3/3 | 3/3 | 3/3 | 3/3 | 3/3 |
| D2 CLAUDE.md から指す | 3/3 | 3/3 | 3/3 | 3/3 | 3/3 |
| D3 別ファイルだけ | 3/3 | 3/3 | 3/3 | 3/3 | 3/3 |

- D2 の 3 回は、最初の操作で `docs/CONVENTIONS.md` を読んだ（CLAUDE.md の指示どおり）
- D3 の 3 回は、最初に `git ls-files`（ファイルは 6 つ）で全体を見て、2 回目の操作で `docs/CONVENTIONS.md` を他のファイルと一緒に読んだ
解釈:
- H1（D1 ≥ D2 > D3 ≈ D0）は**反証された**。D3 も満点。**H3（置き場所は問題でない）が、このセルでは残る**
- ただし理由ははっきりしている: リポジトリが 6 ファイルしかなく、エージェントは最初に全部を見渡すので、どこに置いても見つかる。**このセルは「置き場所」を測れていない（構成概念の不足）**。調査の RepoComplianceBench（実際の OSS で、規則のファイルを自分から開いたのは 347 回中 12 回）とは条件が違う
- D0 は 4 種類とも 0/3 で、決まりごとの検査は既定の振る舞いでは通らない（識別力の土台は確かめられた）
- 「人に渡す」型も、書いてあれば 9/9 で守られた（調査の「Sonnet 4.6 で 0%」は、規則を断る・取り下げる型の場面で、この場面とは違う [事後]）
状態: 終了。次: リポジトリを実際の規模に近づけ（ファイル数を増やし、決まりごとの文書を埋もれさせる）、D2 と D3 の差が出るかを見る（EXP-09）
