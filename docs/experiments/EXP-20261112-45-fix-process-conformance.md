## 補助で分かったこと（主張には使わない。次の作業の入力）

1. **default の終了状態の害は相手より多い（82 対 28 / 28、Fisher + Holm p < 0.0001）**。内訳 H5 71・H7 26・H4 8。B が上がって害が下がっていない。カードの規定どおり「過程の演技」を疑うべき形
2. **原因の候補が 1 つ見つかった（事後の記述）**: default の 91 試行が `suspect`（vanilla 0、v0 1）。92 件の fault はすべて **Bash の拒否（権限モード don't ask）** で、拒否された命令は **状態ファイル `.fix-state.md` を shell で書く / `.gitignore` に追記する** ものが 73 件以上（`echo … >>` 27、`cat > .fix-state.md` 25、`cd /app; echo|cat` 14、`grep -qxF '.fix-state.md'` 9。残りは `git merge-base` 2、`gh api` 2 など）。つまり **既定スキルが求める「状態を戻す」操作の書き方が、実行環境の許可表と合っていない**。害のある試行は suspect で 45/91、そうでない試行で 37/266。H5 71 件のうち 45 件が suspect
3. これは**事後の分解**なので判定には使わない。ただし「スキルの指示 × 許可表の不一致」は fix スキル側（Write ツールで書かせる / 状態ファイルの書き方を固定する）か、アダプタ側（許可表）で直す対象。直した版は別の実験で、同じ規則で測る
4. 害の述語 H5 / H7 がこの状況（書き込みを拒否された後の振る舞い）で何を数えているかは設計者には読めない。**監査役に標本で確かめさせてから**害の数を使う（EXP-44 の H2 と同じ手順）
