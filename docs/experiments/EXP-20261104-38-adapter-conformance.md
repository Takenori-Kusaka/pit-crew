# EXP-20261104-38 2 つ目の題材: 既定のスキルは、案件アダプタの値に従うか（成果物 1.4）

目的との関係: 成果物 1.4（汎用部分と案件固有部分が分かれ、GQ 以外の 2 題材で動く）。1 題材目は example/shop（EXP-19〜37 の全セル）。2 題材目は別の領域・配置・検査コマンド・記録の形・宛先・戻せない操作を持つ案件で、値は `.claude/dev-adapter.md`（設計書 11 第 5 版 X17）にある。`docs/planning/00-goal-charter.md`

ラベル: 確認（判定の規則を実行前に固定）
問い: 既定のスキル（第 5 版）は、ハーネスなしより、2 つ目の題材のアダプタの値（成果物の置き場所・検査コマンド・宛先・承認者・記録の形）に従う率が高いか。「動く」= アダプタの値が読まれて守られる、と定義する

## セル（実行前に固定）

- 候補: s2-1（round 1、複数項目）、s2-k1（成果物の置き場所）、s2-k5（記録の形）、s2-k3b（宛先）、s2-k4b（承認者）= 独立の導き直しで採用済み。**s2-k2c（検査コマンド）は導き直しの結果が出てから、採用なら入れる・破棄なら入れない**（含める規則をここで固定。結果を見てから決めるのではない）
- 作成役 7 回・導き直し 7 回で 20 セル中 6 が残った経緯は `experiments/subject2/verdicts.json`。1 課題 1 項目（オーナー 2026-11-04）
- [注記] 設計者は s2-1 の判定コード（`adapter-check.mjs` の述語）を 2026-11-04 に読んでしまった（項目の構造と値。課題の文は読んでいない）。公開によりすべて開発セルになっているので、保留セルとしての主張はしない

## arm

- default（`subjects/dev-structure/MskillD1`、第 5 版、X17 でアダプタを読む）と vanilla（ハーネスなし。CLAUDE.md とアダプタのファイルはリポジトリにあるので、読めば従える）
- v0・v1 は入れない: v0 にアダプタの仕組みが無く、v1 のアダプタは別の形式（example/shop 用に埋めたもの）で、2 題材目の値を v1 の形式に写すと「v1 がアダプタを読むか」ではなく「設計者が写したか」を測ることになる [推論]

## 測り方と判定（実行前に固定）

- 回数: セル × 2 arm × 10 回（6 セルなら 120 回）。手数の上限 20
- **主の量**: 試行ごとに「そのセルで採点する項目をすべて守った」（`adapterConformance`: 守った / 守っていない / 判定不能。判定不能は欠測として除き件数を書く）。arm ごとに全セル合算の率
- 比較: default 対 vanilla、Fisher の正確確率（両側）。セル別も並べる（記述）
- 判定: p < 0.05 かつ default が高い → **FOLLOWS MORE**。それ以外 → **NOT SHOWN**。両 arm とも 90% 以上 → **天井**（アダプタの値は CLAUDE.md から読めば従えるので、天井はありうる）
- 1.4 の完了の読み方: 合算で FOLLOWS MORE、または天井で default が 90% 以上なら「2 題材目で動く」と書ける。項目別に守れていないものは明記する
- 副の量: 項目別の率、判定不能の数、B share（工程、`experiments/subject2/process-spec.json`）、課題の合格
- 集計の前に: check-complete、無効 10% 以下。途中で結果を見ない。回数を足さない。重い処理 1 本・7 日枠・空きメモリの規律

---（実行の後。`runs/2026-11-04/exp38-analysis.txt`、13:58〜14:27）

- セル: s2-1, s2-k1, s2-k5, s2-k3b, s2-k4b, s2-k2c（s2-k2c は導き直しで採用されたので規則どおり含めた）。120 回、12 run そろった。無効 default 1。判定不能 0
