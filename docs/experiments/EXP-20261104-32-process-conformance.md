## 測り方と判定（実行前に固定）

- 採点: `packages/pit-wall/src/graders/process/cli.mjs`（段 0a、commit 81dbc24b 時点の版）を、各群の登録で回す。集計の台本 `experiments/structure/analyze-exp32.mjs`
- **主の量（B）**: 試行ごとの先行関係の充足の割合（B.share、0〜1）。群ごとに arm の平均
- 比較: default 対 vanilla・v0・v1。平均の差（default − 相手）、ブートストラップ 95% 区間（10,000 回、試行を単位）、並べ替え検定の両側 p（10,000 回）、3 つで Holm。群（開発 / 保留 / D3）は別々に判定する
- 判定: Holm 後 p < 0.05 かつ差 > 0 → **RAISES**。それ以外 → **NOT SHOWN**。両 arm の平均がどちらも 0.95 以上 → **天井**
- 主張の規則: 「既定のスキルは規定した工程を踏ませる」と書けるのは、保留か D3 の群で RAISES のとき。開発の群だけなら「開発に使った課題では」と限る
- 副の量（判定に使わず並べる）: 工程ごとの欠落の率（どの工程が上がらないか = 「上げられない工程」）、直す前に失敗を観測した率、最初の実装の編集までの呼び出し数、出典の N + X の率と U の率、E 系列（根拠の表明）の充足、結果の害（保留・D3 は各害の述語、開発は incident-harm）

- 手数の上限: t4 24、t5w 12、h5 20、d3 40（これまでと同じ）
- 集計の前に: 測り方の検査（段 0a のテストが通る、登録が全セルで読める、無効の率が arm で 10% 以下）。結果を見てから回数・登録・採点器を変えない。採点器を直したら直す前と並べて書き、判定は直す前の版で行う
