# 23 プロセス準拠と根拠の評価の設計

目的との関係: 成果物 1.1（主な量 = 規定したプロセスへの準拠と根拠の裏付け、オーナー 2026-11-03）と 1.3（調査の工程が呼ばれ規定が届く）を、すべてのロールで同じ物差しで測れるようにする。`00-goal-charter.md`
作成: 2026-11-03 / 状態: **案（オーナーの確認待ち）**
根拠: `docs/research/research-process-evidence-evaluation.md`（以下「調査」）。数値と出典は調査に置き、ここには決めたことだけを書く

## 1. 背景

- これまでの主な量は「最終結果の害」だった。小さい課題でも D3 の課題でも、どの arm も害を出さず（EXP-30 4/82、EXP-31 0/24）、ハーネスの差は「全体を一度に読めない大きさ」「古い土台」でしか見えなかった
- 一方、ハーネスなしは最初の書き換えまでに 5〜7 回しか調べず、調査の工程を一度も踏んでいない。531 試行で web の道具を呼んだ試行は 0（呼べたのに）
- 品質の定義（ピットイン開発プロセス ADR-0056・0057: 根拠を証拠と論証で示す。ADR-0012: AI の出力は未検証の入力。設計書 11: 2 案以上の比較・先に調べる・仮説 2 つ以上・決定は残る場所に）に照らすと、測るべきは結果ではなく「規定したプロセスに沿い、根拠と証拠をもって結論を出したか」だった（オーナー 2026-11-03）

## 2. 設計の原則

1. **2 つの系列を分けて報告する**（調査 §1.3）
   - **B（行動の事実）**: 何を開いたか、何を走らせたか、編集の前に何があったか、失敗を観測したか。transcript から決定的に判定する。規則を知らなくても取れる行動なので、ハーネスなしにも公平
   - **E（根拠の表明）**: 判断の理由・代替案・出典をどこかに書いたか。抽出は決定的、質は judge。書く規則を知らない arm に不利なので、書いた場所は問わない
   - B と E を合算しない。「ハーネスで B が上がった」を主な主張にし、E の差は「規則を知らせた効果を含む」と書く
2. **決定的に判定できるものは決定的に**。judge に回すのは意味の対応だけ（言い換えで支えるか、却下案が成立するか、却下理由が案固有か、決め手が観察に結びつくか）。「根拠が書いてあるか」を judge に判断させない（偽の引用で判定が動く）
3. **順序は「必要な先行関係と存在」だけを硬く見る**（Declare 型）。余分な工程・繰り返し・手戻りは減点しない。工程は行動の種類でなく果たした機能で判定する（再現スクリプトでも既存テストの個別実行でもよい）
4. **期待する軌道（T0〜T2）と、採点する判断の点（作る / 作らない、既存を使う / 自作、設計の選択、外から見える名前）は、評価する側が事前に登録する**。エージェントの自己申告で要件を決めない
5. **出典は「書いた時点より前に、エラーでないツール結果に、その中身が見えていたか」で照合する**（自己申告を判定材料にしない）
6. **結果の害は補助の量として必ず並べる**。過程の点だけが上がり結果が上がらない arm は、過程の演技を疑う
7. **測り方も台本で両方向に確かめてから使う**（良い / 悪い成果物、偽の引用、開けなかった呼び出し、正当な別経路）

## 3. 測るもの

### 3.1 Q1 工程（B 系列が中心）

設計書 11 の工程 0〜8 について、調査 §2.2 の表の「決定的な検査」を採る。主なもの:

| 工程 | 決定的な検査（B） |
|---|---|
| 1 調査 | 変えるファイルと呼び出し元を、最初の編集より前に開いた。意味・構造・履歴の検索を別々に数える。土台の確認と、stale のときの取り込み |
| 1 仮説（不具合） | 失敗の観測（Or: 再現スクリプト / 既存テストの個別実行 / 実行して挙動を記録）が、本番コードの最初の編集より前にあり、結果が失敗 |
| 1 既存の解 | 新しい仕組みを作るなら、パッケージ・先行例の検索の実行。挙げたライブラリの実在 |
| 3〜4 テスト | テストの一覧が最初のテストの書き込みより前。テストの書き込み → 実行 → 失敗 → 本番コードの編集の先行関係 |
| 6 テスト評価 | 「通った」の主張ごとに対応する実行があり、その後に関係するファイルの編集が無い（古い証拠） |
| 8 報告 | 報告の主張（件数・ファイル・コマンド・結果・番号）を §3.2 で照合 |

- 主な量: 期待する軌道で必要な先行関係の**充足率**（試行ごとに 0〜1）と、必要な工程の**欠落数**
- `phase-metrics.mjs` の memo の判定を「`notes/` に書いたか」（場所）から「内容の型」（言い直し・計画・仮説のいずれか）に置き換える

### 3.2 Q2 出典（B 系列）

- 引用の抽出（パス・行・記号・コマンド・URL・論文・Issue 番号・数値）→ 正規化 → 書いた時点より前のエラーでない結果に中身が見えたかを照合
- 区分: **O 開いた / P 部分的（範囲外・検索のヒット行だけ・WebFetch の要約だけ）/ M 名前だけ / N 開いていない（内部知識を含む）/ X 存在しない / U 照合できない**。O・P は支えるか S1〜S3・S0 を別に付ける
- 主な量: 判断・報告に使った引用のうち **N + X の割合**（根拠の捏造）。個々の「捏造」の指摘は決定的な N・X だけにする

### 3.3 Q3 判断の理由（E 系列）— 第 2 版（2026-11-04 深夜、オーナー決定: 人のラベル無し）

**judge に文章の質を聞く形をやめる。** 事前登録した「自明でない判断の点」ごとに、次の量と欠陥フラグを出す（`research-machine-only-rationale-evaluation.md` §3）。judge の met / not-met の単一値は出さない。

| 欄 | 中身 | 判定 |
|---|---|---|
| **correct** | 選んだ案は植え込んだ正解か（最終状態の述語。評価側が事前登録） | 決定的 |
| **mentioned** | 植え込んだ代替案を案として挙げたか / 「自明」と宣言したか | 決定的（抽出後） |
| **coherent** | SEURAT の推論（S1 採用案に賛成が無い / S2 反対しか無い / M1 他案の支持が多い / M3 同じ文が賛否両方 / M4 同じ論拠の重複 / M10 採用案の欠点が無い）、基礎付き拡張に採用案が入るか、基準行列があれば Pareto 非劣性（`judge/structure.mjs`） | 決定的 |
| **grounded** | 決め手が参照する観察の O/P/N/X と、理由より前に見えていたか（既存 Q2） | 決定的 |
| **defects** | 定型文（課題との条件付き PMI ≈ 0）/ 規則文の鸚鵡返し（規則あり・なしの対数尤度の差）/ 案の重複（実効案数）/ 観察への被覆 0 / run 横断の反復 | 機械的（段④） |
| **communicable Δ** | 採用の記述を剥がした理由だけを読んだ 8B（2 系統）が採用案を選ぶ率 − 理由なしの率 | 行動（段⑤） |
| **causal Δ** | 理由の前後からの再実行で P(correct) が動くか（2×2 の対角外の標本だけ） | 行動（段⑥、Claude 枠） |
| **unverifiable** | 実行も観察もできない前提（好み・保守性）の数 | 区分（減点しない） |

- 読み方の中心は **2×2（coherent × correct）**。「整合だが誤り」が最優先の精査対象
- **抽出は書式に依存させない**: ローカル 8B に JSON スキーマで {案, 採否, 賛否の論拠, 自明の宣言} を出させ、引用の実在・件数・**同じ内容を表 / 箇条書き / 散文 / 日英に機械で描き直して結果が不変**・2 系統の一致（不一致 = 棄権）で機械検証する（`judge/extract.mjs`）。正規表現で形を拾う検出器（EXP-39 / 40）は使わない
- **「自明」の扱い**: 評価側が「自明でない」と登録した点への自明宣言は mentioned=false。correct は独立に出るので「自明と書いて正解」は 2×2 で分けて読める
- 名前（N1〜N6）は当面測らない（判断の点の 4 量が先）
- 形だけの代替案への対策は defects（特異性 ≈ 0 / 重複）と coherent（M4）に吸収する。量・長さで加点しない

### 3.4 Q4 公平な比べ方

- エージェントが書いた全テキスト（ファイル・commit メッセージ・PR 本文・TodoWrite・最終の返答・サブエージェントへの指示）から内容の型で拾う
- judge には、書式・ファイル名・arm 固有の語を剥がした証拠束を渡す。「同じ実質をハーネスの書式と素の書式で書いた版が同じ判定になる」ことを項目ごとに確かめる（arm 間の公平の直接の検査）。別の LLM に arm を当てさせ、偶然の水準に近いかも確かめる

## 4. judge（第 2 版: 主役から外す）

- **測り方の検証に人のラベルを使わない**（オーナー 2026-11-04「人間が評価しなければならなくなった時点で評価基盤としては破綻」）。正解は 3 種だけ: 構成で決まるラベル（良い成果物への決定的な 1 編集）/ 植え込んだ判断の点の正解 / 書式・順序を変えても判定が変わらない関係。**judge の多数決・一致率は検証に使わない**（条件付き独立の仮定が同じ束を見る陪審で破れる。`research-machine-only-rationale-evaluation.md` 結論 3）
- **各代理指標はセル横断で correct を予測できなければ捨てる**（VeriCoT の「検証通過は正答率を上げる」が型）。これが人のラベルの置き換え
- Claude haiku は、抽出の 2 系統が割れたときの裁定と、残す判定項目の監査（決定的な変異の台本での TNR / 書式・順序の安定 / 論理制約の整合 / arm × judge の差分）に降格する。「精度」とは呼ばず、この 3〜4 数で報告する
- ローカルのオープンモデル（qwen3:8b / granite3.3:8b、ホストの GPU）は、抽出（§3.3）と読み手モデル（communicable Δ）に使う。陪審としては使わない（§10: 負例で偶然以下）

## 6. 危険（調査 §6.1 から主なもの）

- **構成概念の混同**: ルーブリックとハーネスの文面がほぼ同じで、差が「規則を知っているか」を測る → B を主にし、E は別に書く。文面の重なりに印
- **過程の演技（Goodhart）**: 根拠の形だけが増える → 量で加点しない、観察の実在を照合、害を必ず並べる、ルーブリックの一部をハーネスの作者に見せない保留項目にする
- **評価への気づき**: 素の arm も「根拠を書けば評価される」と推測して書く → 差が縮む向き。差が出ないことを「効果なし」とすぐ読まない
- **正当な別経路を罰する**: 制約を機能で書き、正当な別経路の transcript で誤って減点しないことを確かめる

## 11. 記録: 段②の抽出器の検証（2026-11-05、人のラベル無し）

## 13. 読み手測度 第 3 版（案、2026-11-05 夜、オーナー承認待ち）

根拠: `docs/research/research-reader-leakage.md`（LAS / Pruthi / RQ / REV / FRAME / RORA / 反事実 simulatability / ALMANACS / Poché 2026 / 伏せ字方式）。§3.3 の「communicable Δ = P(採用 | 理由) − P(採用 | 理由なし)」は FRAME の RLC 型で、結論の復唱で満点になるのは定義どおりの挙動（欠陥ではなく型の不一致）。測りたいのは「結論を知った上で理由が追加で運ぶ情報」（REV / RORA の問い）だが、読み手が天井にいるため条件付けでは差が出ない → **結論語を消す**（伏せ字）+ **別点の理由を対照**にする。

### 13.1 定義

判断の点 i（植え込んだ案 Oᵢ、採用 a、理由文 rᵢ）、同じ run の別の点 j≠i の理由 rⱼ。**mask(t)** = 全案の識別語（セル設計時に案ごとに登録する名詞句、採用案だけでなく全案）と採否語を、全案共通の 1 つの伏せ字「[案]」に置換（案ごとに別の伏せ字を割ると写像が漏れる — Poché 2026）。案一覧は伏せ字無し、ラベルは呼び出しごとに入替。

```
P_r = P(採用 | mask(r_i), O_i)     理由あり（伏せ字）
P_x = P(採用 | mask(r_j), O_i)     同課題・別点の理由 = 課題語彙からの推測 L2
P_0 = P(採用 | 理由なし, O_i)       事前（arm 間で共有）
P_d = P(採用 | mask(deg_i), O_i)    伏せた退化基線 = 伏せ字の失敗検出（arm 間で共有）
S_i  = P_r − P_x      communicable（理由の内容 L3 の推定）
L1_i = P_d − P_0      結論語の漏れ残り、k_i = 1[L1_i > τ]（τ は合成検証で決める、目安 0.15）
L2_i = P_x − P_0      読み手が課題を解いている度合い（除外せず別掲）
```

- 主読み手 = Jev（確率）、副 = local 8B の案条件付き teacher-forced log p（S^B = ℓ(a) − mean ℓ(o≠a)、符号の見張り、引き分けが出ない）
- 報告: k=0 群と k=1 群を分け、arm 比較は k=0 群の S（中央値・>0 の割合・bootstrap CI）。k=1 群の比率 = 伏せ字器の品質
- **「言及 ≥1 に限る」はしない**（伏せ字後は名指ししない理由も測れる。名指しで絞ると案を列挙する arm だけが残り比較が歪む）

### 13.2 構成による両方向の検証（人のラベル無し、合格条件）

| 合成理由 | 期待 | 検出する欠陥 |
|---|---|---|
| T1 結論の復唱だけ（言い回し 3 通り） | S ≈ 0、k=0 | 伏せ字の取りこぼし率 |
| T2 決め手の観察 1 文（案を名指ししない） | S > 0（m=2 で ≥0.3、m≥3 で ≥0.2） | 読み手が内容→案を結べるか（案記述の具体性 = セル側要件） |
| T3 T2 + 採用案の名指し | S ≈ T2 | 名指しが消え内容だけ残る |
| T4 別点 j の理由 | S ≈ 0 | 対照の妥当性 |
| T5 反対向きの決め手 | S < 0 | 符号が内容に従う |

順序を崩さない: **合成合格 → 実文 77 点で k=1 比率と L2 分布を見る → 判定に使う**（抽出器で「合成で通って実文で崩れた」罠を踏んだため）。

### 13.3 費用

Jev 1 呼び出し ≈ 1,500 tok = 0.000063 ドル。候補 A（k=4、4 条件）は 1 点 1 arm 16 呼び出し = 0.001 ドル、P_0 / P_d を arm 間で共有すれば 0.0006 ドル。77 点 × 4 arm で 0.1 ドル未満。local 8B 副測度は追加支出なし（CPU なら 1 点 20〜45 秒）。

### 13.4 限界

伏せ字は言い換えを逃す（k で点ごとに隔離）。別点対照は同 run 内で話題が重なると S が過小。Jev の較正は独立検証なし（差だけを使う。local との符号一致で見張る）。T2 が通るかは植え込んだ案の記述の具体性に依存し、既存 heldout-s5 / d3 の案記述が満たすかは未確認。
