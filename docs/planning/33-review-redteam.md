## 0. 判定

**ADOPT WITH THESE CHANGES（§7 の 10 項目）。今のままでは採らない。**

理由は 5 つ。

1. 門の数字がすべて未定（案:70）。上限のない門は門ではない。数字は「最初の適用で決める」とあり、決めるのは設計者で、決める時は通したい時である。
2. G3 の定義が憲章の主な量と食い違う。書かれたとおりに当てると、監査で「成り立つ」と判定された Dev の主張の実験を止め、今日の fix の天井は見逃しうる（§1 の F6）。

4. 同系統の問題に対する手当て（植え込みの検出率、別系統の判断モデル）は「解けていないこと」の節にあるだけで、どの門の止める条件にも入っていない（案:67 と案:28 を比べよ）。
5. 案は「足りなかったのは仕組み」と書き（案:11）、出したのは文書である。G1・G5・G6 を機械が強制する箇所が無い。

## 3. 同系統の問題

**案が実際に出しているもの。** P3 の「点検の精度も報告する」（案:17）。§7.1 の 2 つ（植え込んだ誤りの検出率、別系統の判断モデル Jev。案:67）。どちらも門の止める条件に無い。精度が低くても、測っていなくても、G1 は通る。

**足りるか。足りない。**

- 植え込みは、植える人が思いつく誤りしか測らない。台本の対照と同じ穴である（RPG:665 (1)）。
- 今日の監査は確かに効いた（82/83、24/24）。ただし効いたのは、終了状態という機械の物差しがある誤りである。物差しが無い所では監査役自身が弱さを書いている。「画面に出た」は「読んだ」より弱い（qm-audit:241-243）。登録が争えるかは監査していない（qm-audit:234）。fx-e2 の 14 件は不明のまま（log:14-15）。
- 監査役が述語を直し、同じ集合で調整した例が今日ある（log:12）。役の分離は 1 日目に破れた。

**先例が実際に要求しているもの。** ABC I.c.1 は採点の精度を「人との一致」で示す。I.d.1 は検査の正しさを「人などで」確かめる（RPG:533）。HCAST は 945 の記録を人が読んだ（RPG:561）。SWE-bench Verified は 93 人が 1,699 件を読んだ（RPG:572）。機械だけで同じ強さを出した先例は、開いた範囲に無い（RPG:697）。LLM の助けで読んだ HAL は手順が未確認（RPG:578）。プロジェクト自身の調査も、導き直しは別系統かオーナーの抜き取りを勧めている（RPG A-52、`research-experimental-method.md:217`）。

**結論（和らげない）。**

1. 物差しが終了状態にある検査（プローブ・木の一致・HEAD）は、機械だけで信用できる水準に持っていける。
2. 物差しが判断にある検査（正解の登録、何を判定と数えるか、監査役の「実際」の読み）は、**人が一度も読まないかぎり、先例と同じ意味で「検証済み」とは言えない。**
3. 最小の人の関与は次のとおり。計器（ロール × 採点器の版）ごとに 1 回。監査役の判定から層別に 20〜30 件。うち監査役 2 人が割れた件と「判定不能」を優先。オーナーが目隠しで読み、監査役と比べる。1 ロール 1〜2 時間 `[推論]`。これは毎回の採点に人を入れることではない。秤の校正である。ただし 11-04 にオーナーが却下した案（憲章:63）とほぼ同じ物である。隠さない。
4. 人を入れないなら、取れる道は 2 つだけ。(a) 判断に物差しがある項目を主張から外し、終了状態に物差しがある項目だけで主張する。(b) 公開物のすべての主張に「採点器と正解は同系統のモデルだけで確かめた。人は読んでいない」と固定の文を付け、「評価済み」の語を使わない。
5. 新しく人に採点させずに使える人の物差しが 1 つある。過去に人が下した判定の記録（GQ の差し戻し、事故 28 件）である。少ない（差し戻しは 100 PR 中 2 件。案:68）。それでも同系統でない唯一の物差しである。

決めるのはオーナー。

## 4. 実行できるか

- **2 週間で出るもの `[推論]`。** 受け入れた代役と採点器（G4・G2）。弱まった主張の台帳。「G3: 入ったセル 0」の報告が 3 回。オーナーへの相談 1 回。arm の優劣の新しい数字は 0。強いモデルの試走は 7 日枠を食う（憲章:48）。
- **憲章 1.1 に対して。** 定義は「…事前に決めた規則で、**主な量 = 規定したプロセスへの準拠と根拠の裏付け**…を上げるか、上げられない工程を明記している」（憲章:18）。「上げられない」は測った結果である。「測れなかった」は別物である。**「測れるものが無い」の報告を続けても 1.1 は満たさない。** 満たす道は 2 つ。オーナーが 1.1 に第 3 の結果（「この難易度・このモデルの級では測定不能」と範囲つきで書く）を足す。または課題の出どころを実記録に替える（RPG C-16、未実施）。憲章は「易しい課題だけで得た結論は、その難易度の範囲の主張にとどめる」とも書く（憲章:18）ので、範囲つきの主張は憲章の内にある。
- 「測れない」と正直に言い続けること自体は、取り下げを重ねるより良い。ただしそれを成果物の完了と呼んではいけない。

## 7. 採るための変更（最小。番号は上の指摘に対応）

1. **順を直す。** G5 → G4 → G2 → 試走 → G1 → G3 → 本実験 → G1 → G6。G3 は G1 を通った計器の値だけで判定する。（F1、F16）
2. **G3 を主な量で、項目ごとに定義する。** ハーネスなしの率が天井・床でない項目 × セルだけを主の量に入れる。全 arm で常に真の項目と、スキルなしの arm で 0% になるスキル語彙の項目は、arm の比較から外す。選んだ後に、ハーネスなしを別に回して確かめる。（F6、F9、定数の項目。台帳 D-02）
3. **数字を先に、他人が決める。** G1 の標本数・誤読率の上限・判定不能率の上限、G3 のセル数と範囲、追う差の下限、誤差の単位（セル）。最初の適用の前に査読役が案を出し、オーナーが決め、commit する。（案:70、F14、F15、§5）
4. **G1 に門自身の検査を入れる。** 監査役に黙って既知の誤採点を混ぜ、検出率を出す。独立の監査役 2 人で同じ標本を読む。検出率と一致率が上限に届かなければ G1 は不通過。故障は 4 種に分け、arm ごとの「何もしなかった試行」と拒否の数を必ず出す。（§3、F5、台帳 B-48）
5. **G2 の対照は試走の軌跡から取る。** 試走に出た書き方・呼び出しの形を機械で数え、対照に無い形があれば不通過。道具の出力の文字を読む項目は W と同じ扱いにする。W の制限は害の述語にも掛ける（掛けないなら全件読み）。「G2 通過後に G1 が見つけた誤読の数」を毎回公開する。（F2、F4、F8、§2）
6. **G4 を試走の後にも回す。** 代役は記録の無い形に答えを作らず、明示の失敗を返して数える。各 arm のスキルの指示が実行環境で通ることを、拒否 0 の煙試験で確かめる。（F5、F7、§2）
7. **独立を物で守る。** 作成役・導き直し役・監査役は、禁止のファイルが存在しない作業木で走らせ、道具の呼び出しの記録を残す。申告で済ませない。（F10）
