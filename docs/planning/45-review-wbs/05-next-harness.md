# 45 WBS 査読 05 — 次のハーネスを作る人（汎用性）の視点

査読者の立場: 来月、外部監査（ext-audit）のハーネスをこのリポジトリに足して評価したい開発者。木（#7〜#38）が E6 までに何を残し、自分が何をまだ作らなければならないかを確かめた。
「確認済み」= 出典を開いて確かめた。「推論」= 開いた出典からの推論。

## 1. 判定（3 行）

- 木は目的の前半（Dev を評価済みにして公開する）にしか葉が無い。後半（新しいハーネスを半日で設計・半日で試験し、評価を機械化する）を受け持つ段と葉は 1 つも無い。
- E6 まで進めても、外部監査で再利用できるのは植え込みの検査（perturb）と採点器の原則だけである。契約・重要失敗例・Dataset・S2 の強制・ゲートは、どれも Dev と GQ に結び付いた形で作られる。
- GQ のロールへ横に広げる作業（#15）は QM・fix に狭められていて、PO・Platform・監査が抜けている。オーナーの決定を範囲外にする、前と同じ失敗をしている。

## 4. 木がよくできている点（3 つまで）

1. #25 は植え込みの検査を、新しく作らずにキットの `perturb.mjs` で行う（計画 43 `:39`、確認済み）。CI で全ロールに自動で入るので、外部監査にもそのまま効く（`docs/kit-guide.md:60`、確認済み）。
2. #24 の「状態とイベントだけで決まり、ハーネスの文面を読まない」は、どのハーネスにも同じ採点器を使うというオーナーの決定（`00-owner-statements.md:284`）に合っている。N3 の直しで、これがキットの中に残るようになる。
3. #21（ゲートの数字を試行の前に commit する）・#34（試行を回していない役が判定する）・close の決まり（作った役以外が閉じる）は、ロールに依存しない手続きである。雛形（N9）に入れれば、そのまま次のハーネスの規律になる。

## 5. オーナーへの問い（出典で決められないものだけ）

1. **半日の確かめ方**: 「評価に人を入れない」の決定は、ハーネスの出力の採点についての決定と読める。新しいハーネスを作る人の時間（半日）を、オーナー自身が 1 回作って測るのはこの決定の範囲外としてよいか。それともエージェントの手間（N8 の量）だけを代わりの量にするか。出典はどちらとも言っていない。
2. **fix と監査の扱い**: 「GQ で登場したすべてのロール」に fix（pit-crew で新しく作ったロール。会社では rereview に当たる）と、GQ の出荷前の監査（`kit/roles/audit.yaml`）・外部監査（`ext-audit`、GQ には席が無い）のどれが入るか。棚卸し（`research-ganbari-role-process-inventory.md:81-90`）では、GQ の監査は保守の一部として数えられていて、外部監査は入っていない。
