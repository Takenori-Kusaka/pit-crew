# 25 第三者向け監査サマリー: Dev ロールのハーネス評価（2026-11-04 時点）

目的との関係: 成果物 4（第三者が評価を再現できる手順）と 2.3（評価のノウハウ）。この文書は「何を・どの基準で・どう測り・どうだったか」を、証跡の場所つきで 1 ページに書く。`00-goal-charter.md`

## 1. 評価対象

- ハーネス: Dev ロールの既定のスキル `subjects/dev-skill-default`（設計書 `docs/planning/11-dev-role-design.md` 第 5 版から `experiments/structure/build-arms.mjs` で機械的に生成）
- 比べる相手（憲章 1.1）: ハーネスなし（vanilla）/ がんばりクエストのハーネスを丸ごと写したもの（`subjects/ganbari-quest-v0-full`）/ 最初の汎用版（`subjects/role-harness-v1-shop`）
- モデル: claude-sonnet-5-5、Claude Code 2.1.316、Harbor コンテナ（記録の `conditions` 行と `runConditions`）

## 2. 基準（品質の定義）

品質 = 規定したプロセスに沿い、根拠と証拠をもって結論と成果物を出すこと（オーナー 2026-11-03。ピットイン開発プロセス ADR-0056/0057、設計書 11 の原則）。主な量は結果の良否ではなく行動の事実:

| 量 | 中身 | 判定 |
|---|---|---|
| B 工程の先行関係の充足 | 設計書 11 の工程（調査 → 失敗の観測 → テスト → 実装 → 確かめ直し）を順に踏んだ割合 | 記録から決定的（`packages/pit-wall/src/graders/process/`） |
| Q2 出典の裏付け | 引いた出典のうち開いていない・存在しないもの（N+X）の割合 | 決定的（同） |
| 仕事の選び間違い | 越境・取りこぼし・過剰な上げ・浅すぎ・重すぎ | 決定的（`experiments/jobsel/judge.mjs`） |
| 補助: 結果の害 | 事故の型ごとの最終状態の述語 | 決定的（`experiments/structure/incident-harm.mjs` 等） |
| 探索: E 根拠の表明 | 2 案以上の比較・決め手が観察に結びつく 等 | LLM judge（小規模検証のみ、判定には使わない） |

## 3. 結果（事前登録した規則での判定）

| 実験 | 問い | 結果 | 判定 |
|---|---|---|---|
| EXP-32/33 | B を 3 つの相手より上げるか（開発セル / 保留セル / D3） | default 0.92 / 0.85 / 0.93 対 vanilla 0.35 / 0.56 / 0.62、v0 0.62 / 0.74 / 0.72、v1 0.56 / 0.77 / 0.82 | 9 比較すべて RAISES（Holm） |

| EXP-35/36 | 第 5 版は第 4 版より悪くないか | 選び間違い 0/40 対 2/40、B +0.009 [−0.022, 0.038] | 非劣性、採用 |

## 4. 閾値について

プロセス準拠の割合に、業界で確立した合格線は無い（公開のエージェント評価は結果の合格率を相対比較する）。本評価で使った一般の規約は統計的なもの（事前登録、α = 0.05・Holm、効果量と区間、床・天井の規則）だけ。「十分か」の線は所有者の判断で、本文書は線を主張しない。

## 5. 証跡の場所と確かめ方

| 証跡 | 場所 | 第三者が確かめられること |
|---|---|---|
| 実験カード（問い・セル・判定の規則） | `docs/experiments/EXP-*.md` | 規則が結果の前に書かれているか（ローカル git 履歴。公開版は履歴なしの 1 コミット） |
| 実行記録 | `runs/<日付>/<実験>-<セル>-<arm>/results.json`、`raw-*`（記録・最終状態） | 記録から判定を再計算できる（モデル不要） |
| 集計の台本 | `experiments/structure/analyze-exp*.mjs` | `node experiments/structure/analyze-expNN.mjs runs/<日付>` で表を再生成 |
| 採点器のテスト | `packages/pit-wall/test/*.test.mjs`（164 件、両方向） | `cd packages/pit-wall && node --test test/*.test.mjs` |
| 台本の対照 | 各 suite の `script:*` arm、`experiments/*/check-controls.mjs` | 何もしない / 正しい / 害をなす が作ったとおりに区分されるか |
| 保留セルの独立の検証 | `experiments/*/verdicts.json` | 作成役と別の導き直し役の採否（33 セル中 15 採用） |
| 実験ノート（誤りを含む） | `docs/log/*.md` | 直した前後、誤りの記録 |

## 6. 監査上の限界（未達）

- 「実行前にコミットした」証跡はローカル履歴にだけある（公開版はスナップショット）
- LLM judge の人による検証が無い（台本 3+3 件のみ）。作成役・導き直し役・被験体が同じモデル系統
- 保留セルは公開により開発セルに格下げ。一般化の主張には新しい非公開の保留セルが要る
- 第三者の環境での再現と CI（成果物 4）は未実施。再現には Harbor・Docker・Claude の契約が要る
- 長さ・引き継ぎ（複数セッション）の課題は作っていない
