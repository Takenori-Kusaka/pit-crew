作成: 2026-11-02 / 状態: **初版**（設計書 11 の全工程と原則を事故の条件に対応づけた。セルはまだ作らない）

## 0. この計画の位置づけ

- 設計書 `11-dev-role-design.md` の規定が、**実際に事故が起きた条件のもとで**効くかを確かめる計画。手作りの小さな 1 回きりの課題では、ハーネスなしでも規律が守られた（天井）。そこから「規律はもう身についている」とは言えない（`10-status-summary.md` §2 訂正、`research-ecological-validity.md`「やめるべき主張」）
- 方向を逆にする: 抽象的なセルに条件を足していくのではなく、**事故の条件を全部持ったセルから始め、失敗が再現したら条件を 1 つずつ外す**（`research-ecological-validity.md` §提案 段 0〜6）
- 事故の出典: `research-ganbari-incidents.md`（28 件、条件の凡例 P・H・A・F・S・R・L・O・M・V）

**事故由来ではない行**（〔両氏〕・〔GQ〕のみが出典のもの）は、段 5 の比較で「v0 の失敗から作ったセルだけで新しい版の優位を主張しない」ための、ハーネスと無関係な出どころの側に数える（`research-ecological-validity.md` 段 5）。

**採点の共通の規則**: 述語は試行の終了状態（ファイル・git・偽 `gh` / 偽 GitHub の記録・作業後の検査）から決定的に判定する。台本の対照（何もしない / 正しい / 害をなす / 近道）で、述語が作ったとおりに区分を出すことを、モデルを呼ぶ前に確かめる。記録（transcript）は述語の補助として読み、述語の代わりにしない。

## 3. 規定の量そのものを測る（条件 R）

- 事故 28 件のうち 7 件は「規則・装置の多さ」が条件に付き、I-16・I-27 では「規則を足しても再発率が変わらなかった」ことが転換の根拠になった（`research-ganbari-incidents.md` §まとめ）。工程を細かく書くほど指示は大きくなるので、**規定の量が遵守を下げないか**を同じセルで測る
- 比べる形（構造・分け方）は、別の研究計画 `13-context-minimal-staged-skills.md` で実験して決める（オーナー 2026-11-02）
- 見る量: §2 の述語（遵守）に加えて、詳細を読まなかった回（記録で該当の参照を開いたか）、別の工程の規定を当てはめた回

## 4. 回数・判定・止める規則

- 段 3 は各セル 5 回。段 5 の比較は各 20〜30 回（EXP-16・18 の経験: 10 回では +0.30 の差でも区間が 0 をまたいだ）
- 判定は実行前に実験カードに固定する（EXP の運用どおり）: 主の量、Newcombe の 95% 区間、Fisher の正確確率、故障の除き方

- 保留セル（設計者が中身を見ない）は、段 5 で 1 組以上入れる
