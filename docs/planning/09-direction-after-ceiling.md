## 1. 当たった条件

| セル | 何を試したか | 単一セッションの結果 |
|---|---|---|
| A3 / A4 / A9 | 文書の矛盾の裁定 | 値の判断はほぼ常に正しい（33/33 以上） |

| T1 | テストが仕様と矛盾する解けない課題（今日リリースしたい） | 5/5 で矛盾を報告し、何も曲げない |

## 2. 分かったこと（記録から言える範囲）

1. **今のモデルは、役割ハーネスが教え込もうとしていた規律の多くを、すでに単独で守る。** 根拠の扱い、レビュー役の境界、テストの誠実さ。調査の古いモデルの値（解けない課題で約 50% がハック）とは大きく違う。調査も「最新のカードでは現実的なコーディング場面の評価がほぼ飽和」と警告していた
2. **arm の差が一貫して出たのは「案件の約束」だけだった。** 判断記録の書式（v2→v4 で 2/6〜6/6）、ADR に手を入れない約束（書式だけの arm で書き換え・書き足し）。つまり、ハーネスが効いたのは「モデルが知らない、その案件の決まり」を伝えたときだった。これは AGENTS.md の研究（成功率はほぼ上がらないが、標準でない慣習を伝えるのには役立つ）と同じ向き
3. **役割の入口は効くが、1 回きりの課題では振る舞いを変えない。** `/qm` `/dev` で本文は読み込まれたが、行動の形は同じだった（EXP-04・05）
4. **規則は核と案件アダプタに分けられそうに見える**（EXP-02: 87% が核に入りうる。ただし大半は「汎用の規則に案件の値が埋まった形」）
5. **評価基盤は、偽判定を 4 回、走らせる前か後に止めた**（Status 行、ファイル権限、エージェント定義の欠落、同じ長さの書き換えの欠落）

## 3. 次の問いの候補

### 案 B（推奨）: 問いを「規律を教えられるか」から「案件の約束を、どれだけ少ない手間で、確実に伝えられるか」に変える

- 根拠: 差が出たのは約束だけ（§2-2）。オーナーの元の動機（新しい案件でロール別のスキルを作り直す手間）とも直接つながる。約束こそが案件ごとに違い、作り直しが要る部分
- 汎用ハーネスの役割を「規律を教える文」ではなく「**案件の約束を受け取る器（アダプタ）と、それを各役割に確実に届ける仕組み**」と置き直す
- 測るもの: ①約束の遵守率（書式・ラベル・置き場所・やってはいけない操作）②移植の手間（核の編集行数・アダプタの大きさ・別のエージェントがアダプタを埋めるまでの往復）③約束を変えたときに、それが届くまでの手間
- 識別力の見込み: 書式の実験で 2/6〜6/6 の幅が出た。モデルが知らない約束は、単一セッションでは守れない（天井にならない）

### 案 A（補助）: 規律の価値が残るかを、調査で示された条件で 1 つだけ確かめる

- 自分で作ったものを同じ文脈でレビューさせる（自己帰属の偏り、Self-Attribution Bias: 自分の直前の行動を評価させると甘くなる）。新しい文脈のレビューと比べる。「役割分離＝文脈の分離」の効果を測る最小の試験
- これで差が出なければ、規律の面での役割分離の価値は、今のモデルでは小さいと記録する

### 案 C（採らない）: 弱いモデルで識別力を作る

- 識別力は作れるが、オーナーが実際に使うモデルとかけ離れる（外的妥当性が低い）

## 4. オーナーに決めていただきたいこと

1. 問いを案 B に変えてよいか（規律ではなく、案件の約束を伝える器と手間を主に測る）
2. 案 A（同じ文脈と新しい文脈のレビューの比較、10〜12 回）を補助として 1 つ試してよいか
3. 7 日枠の使用率は 0.66（2026-11-01 夕方）。案 B の準備（v1 の器の設計、約束のセル）は主に設計者の作業で、モデルの実行は少ない

## 5. オーナーの判断（2026-11-01、セッションの選択肢で）

- 問いの方向: **案 B（決まりごとを届ける器を比べる）**。根拠は `docs/research/research-conventions-and-self-review.md`
- 案 A（同じ文脈の自己レビュー 対 新しい文脈のレビュー）: **案 B の後に回す**

### 5.1 案 B を「自明でない問い」にするための設計の方針（調査に基づく）

- 規則を入れる / 入れないだけの比較はしない（結論が自明）。比べるのは**届け方**: 置き場所（役割カードに直書き / 核から案件アダプタを参照 / 案件の CLAUDE.md）、役割やサブエージェントをまたぐか、作業の長さ、規則の更新
- 採点は、**規則なしで走らせたときの既定の振る舞いに逆らう規則だけ**を対象にする（Harness-IF の方法）。規則の値はセルごとに変え、暗記で通らないようにする（HANDBOOK.md の方法）。必須の行動と禁止の行動の両方を採点する
- 規則の型を分ける: 出力の形（書式・置き場所）は守られやすく、命名・数量・手順の順序、「人に渡す」型は落ちやすい（調査）。型ごとに識別力を確かめる
