# 05 近道に強い評価と、具体例をハーネスに焼き込まない作り方

作成: 2026-11-01 / 根拠: `docs/research/research-shortcut-and-overfitting.md`（以下「調査」）、試走 `runs/2026-11-01/stage1-pilot-2`
状態: **提案**。オーナーの判断が要る点は §4 に分けた。それ以外は L1 / L2 の汎用機能として設計者が進めてよい範囲と考える。

## 1. 何が問題か

- A3 の正解（60）は「常に ADR を採る」「理由が書いてある方を採る」という近道でも当たる。試走では、履歴を調べずに正解した回があった（試走 1 回目、型 P）
- これは機械学習で繰り返し報告されてきた「正しい答えを間違った理由で出す」問題と同じ形をしている（調査 問い 1）。普段の正解率では、本物の推論と近道を区別できない
- オーナーの指摘（2026-11-01）: オーナーが 1 件について示した「こうなってほしい」を正解として扱うと、近道が精度として報われる。別件が来た瞬間に役に立たなくなる。ハーネス設計にも同じことが言える

## 2. 評価の側でやること（汎用機能、L1 / L2）

### 2.1 規則ごとに「対照の組」を作り、組の全部に通ったときだけ規則を理解したとみなす

- 1 つの規則について、元のセルから**要因を 1 つだけ変えた**セルを作り、近道が外れるようにする（調査 問い 2: 対照セット、最小の書き換え）
- 採点は組単位: 組の全セルで正解の区分に入ったときだけ「規則どおり」と数える（contrast consistency、Gardner ら）
- 裁定の規則についての最初の組（案）:

| セル | 変えた要因 | 正解 | 外れる近道 | オーナーの確認 |
|---|---|---|---|---|
| A3 | — | 古い ADR の値 | 「常に新しい値」「常に設定の値」 | 済（問 2） |
| A4 | ADR の前提が消えている | ADR でない方 | 「常に ADR」「理由が書いてある方」 | 済（問 1） |
| A9 | 新しい値に、今も成り立つ理由がある | 新しい値 | 「常に ADR」「常に古い値」 | **未**（規則 2「より現在に合った根拠を採る」から導けるが、具体例での yes はまだ） |

- 4 つの近道すべてが、組のどこかで必ず外れる。どれか 1 つでも全セルで当たる近道が残るなら、その組は規則を測れていない
- [実装時の訂正] 台本にできたのは 3 つ（常に ADR / 常に一番新しい値 / 常に設定の値）。「理由が書いてある方」はこの 3 セルでは「常に ADR」と同じ値を選ぶので区別できない。区別には「期限切れの理由」対「理由なし」のセルが要り、根拠なし（A7）の領域になる。段階 1 では見分けられない近道として報告に書く（`docs/log/2026-11-01.md`）

### 2.2 近道を台本の対照として走らせる（退化した解き手）

- いまの台本の対照（何もしない / 必ず上げる / 参照解 / 部分解 / 改ざん）に、**近道の台本**を足す: 「常に ADR の値に揃える」「常に一番新しい値に揃える」「設定の値に文書を揃える」など
- 組単位の検査を `pit-wall controls` に足す: 近道の台本はそれぞれ、組の少なくとも 1 セルで `correct` 以外になること。ならなければ、その組は近道を見分けられない（調査: 仮説のみベースライン、ABC の自明エージェント）
- これはモデルを呼ばないので、セルを足すたびに安く回せる

### 2.3 1 セルで言えることを報告に書く

- 報告の各セルに「このセルが見分けられる近道 / 見分けられない近道」を載せる。A3 単体の合格は「理由のない値に負けなかった」までしか言わない（調査 問い 3、ABC の報告項目）

### 2.4 道筋ではなく結果で採点する、は変えない

- 「git log を何回呼んだか」のような道筋の固定は採点に使わない。正当な別解を落とすため（調査: Anthropic）。近道は §2.1 の組で落とす。記録は毎回読む

## 3. ハーネスの側でやること

### 3.1 具体例は規則に一般化してから書く。セル固有の語や値を書かない

- オーナーが確かめた具体例は「規則を書くための材料」として使い、ハーネスには一般化した規則だけを書く
- **漏れの機械検査（L1 の汎用機能）**: arm に渡す本文（スキル、追加のシステムプロンプト）と、セルの材料に固有の語・値（ファイル名、数値、固有の言い回し）を突き合わせ、重なりを報告する。既存の `lintCase`（答えが材料に漏れていないか）の逆向き
- [発見] いまの型 P のポリシー文（`policy-p.md` v1）は、手順 2 の例に「取引先の契約が終わった」を挙げていた。これはオーナーが問 1 で確認した A4 の具体例そのものなので、A4 を評価に使うと答えが漏れる。A3 の試走には影響しない。v2 で例を外し、規則だけにした

### 3.2 作る用・調整用・保留用にセルを分ける

調査（問い 4: AI Agents That Matter、Dwork ら、Blum & Hardt）の考え方を当てはめる:

| 層 | 誰が見てよいか | 何に使うか |
|---|---|---|
| 開発セル | ハーネスの作者が自由に見る | 規則を書く、失敗を読む。オーナーが確認した具体例（A3 / A4 / A11）はここに入る |
| 検証セル | 作者は結果だけ見る | 調整を採るかどうかの判断 |
| 保留セル | 作者は見ない。節目でだけ回す | 「別件でも効くか」の主張。結果を見て直したら検証セルに格下げし、作り直す |

- 保留セルは、開発セルと**題材を変える**（カートと上限値ではなく、別の領域・別の文書の種類・別の時系列）。主張する一般性が高いほど、開発セルから遠くする（AI Agents That Matter）
- 開発セルの成績だけが上がり、保留セルが上がらなければ、過剰適合とみなす。ただし差は採点のばらつきでも出るので、複数回の実行で判断する（Lumer ら）

### 3.3 調整の記録に「どのセルを見て直したか」を残す

- 汚れたセルを後から追えるように、ハーネスの変更ごとに参照したセルを記録する

## 4. オーナーに判断していただきたいこと

1. **A9 を対照の組に入れてよいか**（新しい値に、今も成り立つ理由がある → 新しい値を採る）。規則「より現在に合った根拠を採る」から導けるが、具体例での確認はまだ。具体例の文面は別途お見せする
2. **保留セルを誰が作るか**。ハーネスの作者（私）が作ると、作者が中身を見てしまう。案: 規則の文面だけを渡した別のエージェントに作らせ、台本の対照（参照解と近道）で機械的に正しさを確かめ、私は件数と結果だけを見る。ただし、その場合は保留セルの正しさを人が確かめていない。どちらを優先するか
3. **保留セルの題材の幅**。同じ「文書の矛盾の裁定」の中で題材を変えるところまで（タスク限定の主張）か、別の種類の判断まで広げるか（領域汎用の主張）

2. 「案 A と B のどちらが効果的か。ぱっと見は案 A」→ 設計者の推奨は**案 A に 2 点足したもの**（下記）。**承認済み（2026-11-01）**

### 4.2 問 2 の推奨: 案 A ＋ 独立の再導出 ＋ 捨てる規則

- **案 B を採らない理由**: 保留セルの価値は「調整する人が中身を知らない」ことそのもの（調査 問い 4: Dwork ら、AI Agents That Matter）。作者が作れば、以後のハーネス修正はそのセルに引き寄せられ、保留セルは開発セルと区別できなくなる。案 B の「正しさを確かめやすい」も、確かめる私とハーネスを書く私が同じ思い込みを持つので、見かけほど強くない [推論]
- **案 A の弱点**: 作ったエージェントが規則を誤って当てはめると、正解そのものが間違う（ABC のタスク妥当性）。台本の対照は「採点と環境が壊れていないか」は確かめるが、「正解が規則から正しく導かれているか」は確かめない
- **足す 1: 独立の再導出**。別のエージェントに、規則の文面とセルの材料だけを渡し（正解は渡さない）、正解を導かせる。作成側と一致したセルだけを採る
- **足す 2: 捨てる規則**。不一致・台本の対照で落ちたセルは**直さずに捨てる**。私は捨てた件数と理由の分類だけを見る（中身を見て直すと、私が中身を知る）
- **残る限界**: 作成・再導出・被験体が同じモデル系統だと、同じ盲点を共有しうる [推論、未確認]。報告にこの限界を書く

### 4.3 問 3 の解釈: 「別の種類」はハーネスが扱うと主張する判断の中で選ぶ

- ハーネスが規則を持たない種類の判断で測っても、それは汎用性ではなく範囲外の挙動を測ることになる。そこで「別の種類」は、ハーネスが扱うと宣言している判断（例: レビュー前に設計書を読む / 権限外の質問に答えない）から選び、題材（領域・文書の種類・時系列）も開発セルから離す
- 費用: 種類ごとに台本の対照と再導出が要るので、作る量は種類数に比例して増える
