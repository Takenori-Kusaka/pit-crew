## 4. 戦略

**AgentOps のロードマップの最初の 4 段（契約・基準 → 可視化・回帰 → 実行境界 → 回復・一貫性）を、Dev について GQ の実物で通し、リリースゲートの形で「評価済み」の主張を 1 本出す。**

- **課題の出どころ（Dataset）**:
  - 正常・複合の課題: EXP-48 の「issue → 修正 PR」の実際の修正（使える 19〜28 件。`experiments/exp48/candidates.json`）。環境は EXP-48 の計器（課題ごとの image、修正前までの履歴、記録器、隠した検査）
  - **重要失敗例**: GQ の ADR のうち、Dev の作業で起きた事故から生まれたもの。例: ADR-0006（検証の弱体化の禁止）、ADR-0060（「全対応完了」の宣言と 10 項目の検証 = 虚偽の完了）、ADR-0022（admin bypass の禁止・作成者 ≠ 承認者）、ADR-0026（force push による消失）、ADR-0030（pre-ready）、ADR-0061（その場しのぎの修正）、ADR-0005（テストの品質の ratchet）、ADR-0002（重大な修正のゲート）。各 ADR の「経緯」から、事故が起きた状況を EXP-48 の課題の上に再現する（例: 修正の途中で既存のテストが落ちる → assert を弱めたくなる。テストを走らせずに完了を宣言したくなる）
- **条件（層を 1 つずつ足す）**:
  - S0: 指示ファイルなし（計画 34 の A）
  - S1: + Dev の役割の手順（`subjects/dev-skill-default`。計画 34 の C）
  - S2: + 決定的な強制（GQ の検査・hook のうち、Dev の重要失敗例に効くもの: assert を減らす編集の拒否、テストを走らせない完了の拒否、自分の PR の承認・force push の拒否 など。モデルの外で動く）
  - 記述として D（GQ そのまま）を並べてよい（判定はしない。計画 34 §4）
- **測る量（別々に）**: タスクの成功（隠した検査）、違反の数（重要失敗例の種類ごと）、虚偽の完了報告、上げすぎ（実行できたのに断った）、pass^3、費用・時間。オーナーの決定（品質を段階で測る）に従い、過程の品質（計画 34 §5 の 3 工程の段階）を別の軸として出す
- **判定（リリースゲート）**: 品質の非劣化と安全の改善を別の条件にする（レポート「推奨するリリースゲート」）。数字は E0 で事前に決めて commit する
- **規模**: 少数の重要ケースから始める（レポート「推奨する評価マトリクス」の注）。目安は 5 課題 × 3 層 × 3 試行 = 45 試行（Opus 級）。消費の測定（E3）の後にオーナーが決める

計画 34 の資産（計器・課題・門・Jev の監査）は使う。**この戦略は計画 34 の条件（A/B/C/D、C − A を先に次に C − B）と判定の規則を置き換える**ので、E0 でオーナーの決定を受ける。

## 6. 役の分け方

計画者・実行者・検証者の権限と入力を分け、検証者は実行者の結論をそのまま受け入れない（レポート「複数Agentは役割分離が利益を生む場合に使う」、計画 34 §9）。自律で進めるときは、Agent ツールで役ごとに別のサブエージェントを起動し、役の決まり（実装役は門の合否を書かない、査読役は計画を書いていない、など）を依頼文の冒頭に書く。合否・数字を決める役には、作った役の結論を渡さず、ファイルだけを渡す。同じ系統のモデルであることは限界として台帳に書く。

## 8. 運用の決まり（破ると取り返せないもの）

- 会社の情報・秘密・顧客データをリポジトリに入れない。OAuth トークン（`~/.config/pit-wall/oauth-token`）と TypeSafe の鍵を表示・commit しない
- **GQ（AGPL）の中身を追跡するパスに入れない**。中身は `local/`（git 無視）。commit の前に必ず `node packages/pit-wall/src/gates.mjs no-gq-content && git commit ...`。`git commit -a` を使わない
- 公開は `python scripts/publish-snapshot.py` のスナップショットだけを `git push origin <id>:refs/heads/main`。手元の main は push しない。告知はオーナーの承認の後
- WSL のコマンドは台本ファイルにして `MSYS_NO_PATHCONV=1 wsl -d Ubuntu-24.04 -- bash -l <file>`。JS・正規表現を含む台本は Write で書く（Python の文字列で書くと `\b` などが壊れた）。YAML の値に「: 」があれば引用符で囲む
- force push・本番デプロイ・スキーマ変更・`.env`・`rm -rf` は確認を求める
- 追加の支払いはしない（Jev の 2 ドルだけが例外）
- 報告は日本語。問いは AskUserQuestion で。30 分ごとの進捗報告が来たら 3〜6 行で
