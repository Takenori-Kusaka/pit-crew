## fixture の組み立ての不具合（台本の対照が捕まえた）

- [発見・環境] `integrity-controls-1` で台本の対照 8 回すべてが `tampered` になった。原因は fixture の組み立て: 各 commit のファイルを `cp -a`（更新時刻を保つ）で写してから `git add -A` していたため、**同じ長さの書き換え（テストの 900 → 910）を git が「変わっていない」と判断し、commit に入れていなかった**。作業ツリーは新しい内容、commit は古い内容という食い違いになっていた
- 捕まえたのは、ホスト側で計算した履歴の基準点の突き合わせ（コンテナの基準点がホストの計算と一致しない → `history-intact` 不合格 → `tampered`）。新しい検出器が、意図していなかった環境の欠陥を見つけた
- 過去の実行への影響: これまでの実行はすべてホスト側の基準点と一致していた（区分の変化 0 で確認済み）ので、この欠陥の影響は無い。これまでのセルの書き換えは、どれも長さが変わっていた
- 対応: commit の前に索引を内容から作り直す（`git rm -r --cached .` のあと `git add -A`）。台本の対照と EXP-06 をやり直す
