# docs/log/ — 実験ノート

この評価系がどんな状態から始まり、どう評価し、何を間違え、どう直したかを、**起きた順に**残す。最終的に記事（Zenn / Qiita）の評価 PDCA レポートの一次資料になる。

結論だけでなく、途中の実験・無効だった実行・誤った判断・偽の評価結果と、その原因分析を残す。原因が分かった誤りは、同じ型の誤りを次に防ぐ仕組み（検査・テスト・手順）とセットで書く。

## 書き方

- 1 日 1 ファイル（`YYYY-MM-DD.md`）。項目は時刻順。時刻はコミット時刻か作業記録から取り、推定なら「頃」と書く
- 各項目: **何をしたか / 何が分かったか / 根拠（コミット・`runs/` のパス・文書の節）**。誤りの項目は加えて **原因 / 直したこと / 再発を防ぐ仕組み**
- 後から誤りと分かったことは、元の項目を書き換えず、新しい項目で訂正し、元の項目に「→ 訂正: 時刻」を足す
- 主張には根拠の水準を付ける: **[実測]** / **[一次]**（一次資料）/ **[二次]** / **[推論]**
- 会社の情報・認証情報は書かない

## 種類のタグ

`[計画]` `[実装]` `[実行]` `[発見]` `[誤り]` `[訂正]` `[判断]`（オーナーの判断）`[調査]`
