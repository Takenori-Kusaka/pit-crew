# D1 スモークテストの記録（2026-10-31）

環境は WSL2 Ubuntu 24.04、Claude Code 2.1.314、Max サブスクの認証（API キーは使っていない）、bubblewrap 0.9.0、socat 1.8.0.0。

## 結果

| ケース | 内容 | with | without | Δ | 試行 |
|---|---|---|---|---|---|
| conflict-readonly（S1 相当） | 採択済みの ADR（50）と設計書（100）が食い違う | 1.00 | 1.00 | 0.00 | 2+2 |
| conflict-tie（S2 相当） | 同格の設計書 2 本（100 と 60）が食い違い、どちらが優先かの規定がない | 0.67 | 0.00 | +0.67 | 3+3 |

- **S1 は天井効果が出た。** 素の状態でも「採択済みの ADR が優先」と判断できるので、差がつかない。calibration ではこのケースを除くか、もっと難しくする。
- **S2 は差がついた。** 素の状態では 3 回とも数値を 1 つ選んで実装しようとした（判断を上に上げなかった）。スキルありでは 3 回中 2 回、上に上げた。
- 試行回数が少ないので、この数字は探索段階のもの。統計的な判定はしない。

## 分かったこと（設計に反映する）

1. **評価器も先に検証する必要がある。** 最初の試行では `context.add_dirs` で文書を渡したが、作業ディレクトリに文書が置かれず、エージェントが見つけられなかった（スコア 0.33。これはケース側の不具合）。文書などの fixture は `scaffold_script` で作業ディレクトリに書き出す。
2. **会話記録（transcript）は取得できる。** 結果 JSON の `tracePath` に `trace.jsonl`（stream-json 形式）があり、`--keep-temp` を付けると残る。中身は tool_use / tool_result / text、`permission_denied`、`rate_limit_event`（5 時間枠の状態）。これを ATIF に正規化する変換元にする。
3. **使用枠の消費を測る手がかりがある。** trace の `rate_limit_event` に 5 時間枠の状態とリセット時刻が入っている。`costUsd` は定価換算の推定値で、1 run あたり約 $0.07（請求額ではなく、枠の消費量を見積もる目安）。
4. **mock MCP の採点は両 arm で除外される。** plugin が宣言した MCP サーバの `mock_calls` は、without arm にサーバ自体が存在しないため、両方の arm で採点から外される。label を付け替えた操作の判定には MCP mock を使わない。代わりに、arm に依存しない `gh` の shim（PATH の先頭に置く記録用スクリプト）を使う。これは Harbor にも持ち込める。
5. **所要時間**：1 run あたり 20〜35 秒。
